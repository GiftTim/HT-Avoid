b. 목표 / 확정 컨셉
================================================================

  프로젝트명 "HT-Avoid" = Helltaker(HT) + Avoid(피하기).
  이 문서는 (1) 게임의 핵심 반복 루프(코어 게임플레이 사이클)와
  (2) HT-Avoid를 "플레이 가능한 게임"으로 완성하기 위한 개발
  우선순위를 한 문서에서 함께 관리한다.
  개별 기능 착수 시에는 이 문서를 "참고 계획"으로 인용하며
  [2. ChangePlan] 문서를 별도로 작성해 진행한다.

  [ 확정 컨셉 (26.10.01) ]

  기본 축 : 헬테이커 + 피하기 게임. 헬테이커의 "퍼즐 한 판" 자리에
  "피하기 한 판"이 들어간다.

  1. 실패하면 그 판만 즉시 재도전 (헬테이커식)
     - 피하기에서 실패하면 타이틀/체크포인트로 돌아가지 않고 그 판을
       바로 다시 시작한다
  2. 대화 선택지를 틀리면 피하기 게임으로 되돌아감
     - 헬테이커는 "오답 → 즉사 → 그 대화만 다시"지만, 이 게임은
       "오답 → 그 챕터의 피하기 판을 다시 플레이"로 한다 (오답의
       벌칙이 피하기 한 판)
     - 피하기를 다시 깬 뒤에는 그 대화를 처음부터 다시 본다. 한 판이
       1~2분으로 짧고 대사도 헬테이커보다 길지 않게 쓸 것이라 부담이
       크지 않다고 판단
  3. 챕터마다 새 캐릭터 1명을 만나 동료로 삼는 구성
     - 그 챕터의 캐릭터 = 그 판의 피하기 상대(보스)
  4. 짧은 분량 : 챕터 8~10개, 플레이 타임 1~2시간
  5. 일직선에 가까운 진행
     - 호감도/본격 분기 없음. 피하기 결과(피격 횟수 등)에 따라 대사
       몇 줄만 바뀌는 정도
  6. 피하기는 순수 회피 : 방향키 이동 + 점프로 피하기만 한다
     - 플레이어 공격 없음 (26.09.20 부활 결정을 다시 번복)
     - 이동 축은 좌우 + 점프. 앞 방향키는 전진에 쓴다 (26.10.02 변경 —
       누르고 있는 동안에만 앞으로 나아감. 아래 방향키는 쓰지 않음)
  7. 피하기의 형태는 "남극 탐험" 베이스
     - 플레이어가 실제로 맵을 돌아다니는 게 아니라 배경이 흘러가면서
       "앞으로 나아가는" 느낌을 준다
     - 맞은편에 있는 적(그 챕터의 캐릭터)이 보내는 공격을 좌우 이동과
       점프로 피하면서 전진한다
     - 시점 : 원작처럼 뒤에서 보는 유사 3D. 적과 공격이 화면 안쪽에서
       다가오며 커진다 (옆에서 보는 횡스크롤이 아님)
  8. 클리어 조건 : 제한시간 안에 목적지 도착
     - 제한시간은 한 판에 1~2분 남짓
     - 시간 안에 도착하지 못하면 패배 → 그 판 즉시 재도전 (1번)
     - 공격에 맞아도 죽지 않고 시간만 잃는다 (남극 탐험식).
       패배 조건은 시간 초과 하나뿐. 체력(하트)은 없음
  9. 스토리 컨셉 : 동화나라 (26.10.01 확정)
     - 주인공(플레이어)이 동화 세계를 헤쳐 나아간다
     - 동화의 주인공들이 적이다 → 챕터 1개 = 동화 1편, 그 동화의
       주인공 = 그 판의 상대(보스)이자 클리어 후 동료 (3번과 결합)
     - 주인공이 누구인지, 왜 동화 세계를 지나가는지, 어떤 동화를 쓸지,
       최종 보스, 톤은 미정 (k절)

    ┌─────┐       ┌─────────────┐       ┌────┐
    │ VN  │ ──▶ │ 피하기 게임   │ ──▶ │ VN │
    │     │      │ (순수 회피)   │      │    │
    └─────┘       └─────────────┘       └────┘
        ▲            ▲   │ 실패             │ 선택지 오답
        │            └───┘ (즉시 재도전)    │
        │            ▲                      │
        │            └──────────────────────┘ (피하기로 되돌아감)
        │                                   │ 정답
        └────── (다음 챕터로 반복) ─────────┘

    1챕터 = 1사이클. 챕터 8~10개를 반복 → 마지막 보스 스테이지 클리어
    (챕터가 진행될수록 피하기 난이도/규모가 점점 확대됨)

  [ 1사이클(1챕터) 흐름 ]
    1. VN        : 상황 설명, 그 챕터의 새 캐릭터 등장, 도입부
    2. 피하기    : 그 캐릭터가 상대(보스)인 실시간 회피 한 판 (1~2분).
                   맞은편에서 오는 공격을 피하며 제한시간 안에 도착하면
                   클리어. 시간 초과로 실패하면 그 판만 즉시 재도전
    3. VN        : 클리어 후 대화 + 선택지. 정답이면 캐릭터가 동료가
                   되고 다음 챕터로. 오답이면 2번(피하기)으로 되돌아가고,
                   다시 깬 뒤 이 대화를 처음부터 다시 봄
    → 반복 → 마지막 보스 스테이지 → 클리어

f. 각 파트가 담당하는 역할
================================================================

  VN         : 서사 전달, 챕터별 캐릭터와의 관계 형성(동료 영입),
               다음 구간의 동기 부여. 선택지 오답은 피하기 판 재플레이로
               이어짐
               (기존 엔진 그대로 사용 — 대사/커맨드/캐릭터/그래픽/오디오)

  피하기     : 순간적인 텐션/액션 담당. 플레이어는 좌우 이동과 점프만으로
               맞은편 적의 공격을 피하며 제한시간 안에 목적지에 도착하는
               것이 목표 (남극 탐험식, g절).
               결과(피격 횟수, 재도전 횟수 등)는 다음 VN 파트의 대사
               몇 줄을 바꾸는 정도로만 반영 (본격 분기/호감도 없음.
               VariableStore를 통해 VN 쪽 조건문과 연결, h절 참고)

  최종 스테이지(보스) : 사이클의 마지막 관문. 일반 스테이지보다
               공격 패턴/페이즈가 훨씬 복잡한 스테이지. 클리어 방식은
               일반 스테이지와 같음 (제한시간 내 도착)

g. 구현 시 필요한 신규 시스템

  1. 피하기(Avoid) 미니게임 엔진 (순수 회피, 26.10.01 확정)
     - 형태 : 남극 탐험 베이스 (26.10.01 확정)
       · 배경이 흘러가며 전진하는 연출. 플레이어는 좌우 이동 + 점프만
       · 맞은편 적이 보내는 공격 패턴을 스폰 → 플레이어 충돌(피격) 판정
       · 진행 거리(목적지까지 남은 거리)와 제한시간 타이머가 필요
       · 시점 : 뒤에서 보는 유사 3D (26.10.01 확정). 적과 공격이 화면
         안쪽(위)에서 다가오며 커짐. 좌우 = 피할 위치, 점프 = 바닥으로
         오는 공격 넘기
       · 구현 방법 (확정 26.10.02 — 일주일 일정에 맞춘 선택) :
         실제 3D 공간 + 원근(Perspective) 카메라 + 세워둔 2D 스프라이트
         - 플레이어는 X축(좌우)과 Y축(점프)만 움직이고 Z는 고정.
           좌우는 한계 안에서 자유 이동 (확정 26.10.02, 레인 단위 아님)
         - 공격/장식 오브젝트는 먼 Z에서 생성돼 플레이어 쪽(-Z)으로 이동
           → 다가오며 커지는 효과, 앞뒤 가림, 좌우 원근이 카메라만으로
           자동 처리됨 (크기/위치 계산 코드를 직접 짤 필요 없음)
         - 바닥은 평면 하나에 텍스처를 스크롤(UV 오프셋)해서 전진 연출
         - 충돌은 3D 콜라이더 트리거 (Physics 3D 모듈 이미 포함됨)
         - 채택 이유 : 2D 에서 거리별 크기/위치를 직접 계산하는 원작식은
           투영 수식, 그리기 순서, 판정을 전부 손으로 짜야 해서 일주일
           안에는 위험. Unity 6 / URP 17 프로젝트라 추가 패키지 불필요
         - 주의 : 기존 Avoid 코드는 2D 물리(Rigidbody2D/Collider2D/
           OnTriggerEnter2D) 기반이라 3D 물리로 새로 작성해야 함.
           Avoid.unity 카메라를 Orthographic → Perspective 로 변경
       · 이동 : 기존 중력 기반 옆시점 이동(MovementRigidbody2D)을 좌우
         전용 이동 + 점프로 교체 (새 스크립트)
       · 피격 : 죽지 않고 시간 손실만 (26.10.01 확정)
         - 공격 종류에 따라 특수 연출과 함께 "멈춤(경직)" 또는 "뒤로
           튕김(넉백 = 진행 거리 감소)" 반응이 다르게 나옴
         - 어느 쪽이든 결과는 도착이 늦어지는 것 = 시간 손실
         - 공격 데이터에 반응 종류/경직 시간/넉백 거리/연출을 담음
         - 피격 직후 짧은 무적 시간을 둬서 연속 피격으로 시간이 한꺼번에
           날아가는 것을 막음 (권장 — 수치는 플레이테스트로)
       · 시간 초과 후 재시작 화면 (26.10.04 확정, 나중에 구현할 디테일) :
         지금(3-c)은 프로토타입이라 "TIME OVER" 문구 후 씬을 다시
         로드하는 것으로 끝냄. 이후에는 컵헤드처럼 재시작 전에 "어느
         정도 달렸는지(진행률)"와 "남은 패턴이 몇 개인지"를 보여준다.
         → 스테이지 프로필(3-a)에 패턴 목록과 각 패턴의 발동 거리를
           담아 두면 진행률/남은 패턴 수를 거기서 바로 계산 가능.
           도달 거리·지나간 패턴 수는 AvoidSession 에 남길 것
     - 조작 : 마우스 없이 키보드만 사용 (26.09.20 확정, 26.10.01 갱신)
       · 이동 : 방향키 왼쪽/오른쪽
       · 전진 : 방향키 위 — 누르고 있는 동안에만 전진 (26.10.02 변경,
         자동 전진 아님). 떼면 제자리, 제한시간은 계속 흐름
       · 점프 : Space (26.10.02 변경, Alt → Space). 점프 횟수는
         AvoidPlayerMovement 의 maxJumpCount 로 조절 (기본 1)
       · 피격 반응(멈춤/넉백) 중에는 좌우 이동/점프 불가, 공중이었다면
         바로 떨어짐 (26.10.02)
       · 공격/조준 : 없음 (26.10.01 삭제)
       · 이유 : 마우스가 필요 없어야 콘솔(게임패드)로도 플레이할 수
         있음. 십자키 + 버튼 1개라 게임패드에 그대로 대응됨
       · 현재 구현 (AvoidInput.inputactions, 26.10.03 확인) :
         Move = 방향키 좌우 1D Axis + 게임패드 십자키/왼쪽 스틱,
         Jump = Space + 게임패드 buttonSouth, Forward = 방향키 위 +
         게임패드 십자키 위/왼쪽 스틱 위. Attack 액션은 제거됨.
         Player 에는 PlayerInput / AvoidPlayerController /
         AvoidPlayerMovement / PlayerHit 만 붙어 있음
       · Player/Gun 1 오브젝트는 26.10.03 삭제함. 남은 정리 : 안 쓰는
         스크립트 파일(PlayerAttack / AimCursor / PlayerHP /
         MovementRigidbody2D 등)을 지울지 보관할지 결정
     - 클리어 조건 : 제한시간 안에 목적지 도착 (26.10.01 확정)
       · 제한시간은 한 판에 1~2분 남짓. 스테이지별 정확한 시간/거리는
         미정
     - 실패/재도전 처리 : 그 판만 즉시 재도전 (26.10.01 확정)
       · 제한시간 안에 도착하지 못하면 패배 → 같은 판을 처음부터 다시
       · 패배 조건은 시간 초과 하나뿐. 피격은 시간 손실로만 이어지고
         체력(하트)은 없음 → 기존 PlayerHP 는 사용하지 않음
       · 타이틀 복귀/목숨 3개/대기방/보스 HP 유지 방식은 쓰지 않음
     - 난이도 확대 : 챕터가 진행될수록 공격 패턴/규모 확대
     - 폴더 : Assets/Scripts/Avoid/ (2단계에서 생성됨)

  2. 사이클 매니저 (GameCycleManager 가칭)
     - VN → 피하기 → VN 순서로 씬/상태를 전환하는 상위 컨트롤러
     - 피하기 결과값을 다음 VN 파트로 전달하는 역할
     - 신규 폴더 제안 : Assets/Scripts/Core/GameFlow/ (또는 프로젝트 루트 Core)

  3. VN ↔ 미니게임 전환 커맨드
     - 기존 CommandManager에 새 명령어 추가 (예: [startAvoid])
     - CMD_DatabaseExtension을 상속한 새 확장 클래스로 구현 (리플렉션 자동 등록)
     - 씬 레벨 연결 방식 : 애디티브 씬 로딩(LoadSceneMode.Additive) 채택

     - 선택지 오답 시에도 같은 커맨드로 피하기 판에 재진입 (h절)


================================================================
h. 기존 VN 엔진과의 연동 지점
================================================================

  - 씬 레벨 연결 방식 : 애디티브 씬 로딩 (확정, 26.09.14)
    · VN 씬(VisualNovel.unity)을 언로드하지 않은 채 미니게임 씬(예:
      Avoid.unity)을 SceneManager.LoadSceneAsync(씬명, LoadSceneMode.
      Additive)로 위에 얹는 방식
    · 채택 이유 : DialogueSystem/CharacterManager/HistoryManager/
      VariableStore 등 VN 핵심 싱글톤이 DontDestroyOnLoad 처리가 안
      되어 있어서(AudioManager만 예외) 단일 모드 LoadScene으로 씬을
      완전 교체하면 전부 파괴됨. 같은 씬 안에서 오브젝트 SetActive
      토글하는 대안도 있었으나 콘텐츠가 한 씬에 계속 쌓여
      비대해지는 문제가 있어 기각
    · 주의 : 애디티브 로딩 시 VN 배경/그래픽 패널이 미니게임 씬 뒤에
      그대로 남아있으므로, 미니게임 씬 카메라의 Depth를 VN 카메라보다
      높게, Clear Flags를 Solid Color(또는 Depth Only)로 설정해 가려야
      함 (에디터 작업)
    · 상세 설계 : Assets/Docs/2. ChangePlan/[26.09.14_20.24] 피하기
      게임 기초 구조 및 VN 연결.txt 참고
  - VN 복귀 트리거 (26.10.04 교체 완료) : [wait]startAvoid() 가 Avoid
    씬을 얹고 AvoidSession.IsFinished(= 도착 클리어) 가 될 때까지
    기다렸다가 결과를 변수로 쓰고 VN 으로 복귀. 대본은 위에서 아래로
    선형으로 쓰면 됨 (endAvoid 는 옛 대본 호환용으로만 남김)
  - 선택지 오답 → 피하기 재진입 (26.10.04 구현·확인) : 오답 결과 줄에
    [wait]startAvoid() 다음 줄에 [wait]restartDialogue() 를 쓰면, 그
    대본 파일(Conversation)을 첫 줄부터 다시 재생. 그래서 "클리어 후
    대화"는 도입부와 별도 파일로 두고 도입 파일 끝에서
    load(-f 경로) 로 이어 붙임 (예 : Test/AvoidChapterTest.txt →
    AvoidChapterTest_After.txt). 한계 : 선택지 한 단계만 확인함, 중첩
    선택지는 미확인
  - VariableStore : 피하기 결과값(피격 횟수, 재도전 횟수 등)을
    변수로 저장 → VN의 LL_Condition이 이 변수를 읽어 대사 몇 줄을
    바꾸는 데 사용 (예: "한 번도 안 맞고 깼을 때의 대사")
  - CommandManager : 대사 중 [startAvoid(스테이지명)] 같은 커맨드로
    미니게임 씬/모드 진입 (애디티브 로딩 사용)
  - VNGameSave : 챕터 진행도(몇 번째 챕터, 클리어 기록 등)도
    함께 저장해야 함 → 기존 세이브 데이터 구조 확장 필요
  - 자동저장 체크포인트 : 불필요 (즉시 재도전 확정, 26.10.01).
    저장은 챕터 단위 진행도만 있으면 됨

    까지의 거리/사용 패턴 목록/배경 등을 담음

    않는 상태라 이걸 붙여야 비로소 "피하기" 게임이 됨. 이 단계가

    - 이유 : 헬테이커처럼 캐주얼하게 "VN → 게임 한 판 → VN"만 반복하는
      구조로 범위를 줄이기 위함
    - 카드/공격 포함 원안은 Assets/Docs/6. Archive/ 의 보관본에 원문
      그대로 보존

  ■ "피하기" 세부 규칙 중 미정인 것
    (확정된 것 — 26.10.01 : 이동 축 = 좌우 + 점프만 / 형태 = 남극 탐험
     베이스 / 시점 = 뒤에서 보는 유사 3D / 클리어 = 제한시간 1~2분 내
     도착 / 피격 = 시간 손실만, 하트 없음.
     26.10.02 : 유사 3D 구현 = 실제 3D 공간 + 원근 카메라 + 세워둔 2D
     스프라이트 / 좌우 이동 = 자유 이동)
    - 피격 반응 : 공격별로 특수 연출 + 멈춤 또는 뒤로 튕김 (확정
      26.10.01, g절). 공격별 경직 시간/넉백 거리/무적 시간 수치는 미정
    - 스테이지별 정확한 제한시간/거리, 남은 시간·거리 표시 방식
    - 전진 속도 : 확정 (26.10.02) — 자동 전진이 아니라 앞 방향키를
      누르고 있는 동안에만 일정 속도로 전진. 가속/감속 조절은 없음
    - 보류 아이디어 (26.10.02 — 결정 안 함, 기억만) : 테일즈 러너식
      대시(가속) 조작. 넣으면 전진 속도를 플레이어가 조절하게 되어
      버튼이 하나 늘고 제한시간 난이도 계산이 달라짐. 넣는다면
      "누르는 동안 빨라지고 게이지가 닳는" 단순한 형태가 현실적.
      1챕터가 돌아간 뒤(3일차 이후) 다시 검토
    - 공격 패턴 개수/종류, 페이즈(시간대별 변화) 디테일
    - 히트박스/판정 방식 세부
    → 확정되는 대로 별도 [2. ChangePlan] 문서로 세부 설계 진행

  ■ 조작 방식 : 키보드만 — 방향키 좌우 이동 + 방향키 위 전진 + Space
    점프. 공격/조준 없음, 마우스 미사용 (26.09.20 확정, 26.10.01 공격
    삭제, 26.10.02 전진 키 추가 + 점프 Alt→Space)
    - 근거 : 콘솔(게임패드) 플레이 가능하게 하려는 목적 (g절 참고)
    - 확인 사항
      · VN 쪽 조작 : VisualNovelInput 은 키보드만 바인딩됨(Space/
        Enter/좌우 방향키 등). 게임패드 바인딩 추가 필요. 선택지
        (LL_Choice) UI가 마우스 클릭 전제인지는 확인 못 함 → 콘솔
        대응하려면 방향키/스틱 + 확인 버튼으로 선택 가능해야 함
      · 콘솔 "출시"가 목표인지, PC에서 게임패드 지원 정도인지는 미정
        (콘솔 출시는 플랫폼별 빌드/인증/세이브 방식 등 별도 작업이
        크게 필요 — 지금은 "입력을 키보드/패드로만 설계"하는 범위)

  ■ "1단계 VN 완성"의 범위 확정 (26.09.14)
    대화 시스템 + 캐릭터 + 시나리오 읽기(재생) + 선택지로 확정. 메인메뉴/
    세이브로드 UI/설정/갤러리/실제 스토리 콘텐츠(콘텐츠 파이프라인)는

  ■ 선택지 결과가 변수에 자동으로 남지 않음 (VN 엔진, 확인 26.09.13)
    LL_Choice는 선택한 결과 대사만 재생할 뿐, "어떤 선택지를 골랐는지"
    자체를 변수로 자동 기록하지 않음. 나중에 그 선택을 조건문에서
    쓰려면 작가가 매번 선택지 결과 줄 안에 변수 대입 커맨드를 직접
    적어야 함. 일직선 진행 확정으로 필요성은 줄었으나, 콘텐츠 분량이
    늘면 자동화를 검토할 것

  ■ 스토리 (26.10.01 갱신)
    - 확정 : 동화나라 컨셉. 동화의 주인공들이 적이고, 플레이어는 그
      동화 세계를 헤쳐 나아감 (b절 9번)
    - 미정 : 주인공(플레이어)이 누구이고 왜 동화 세계를 지나가는지
    - 미정 : 챕터별로 쓸 동화와 캐릭터 (챕터 수와 함께 확정).
      캐릭터마다 원작 소품에서 따온 공격 방식 + 피격 반응(멈춤/넉백)을
      정해야 함
    - 미정 : 동화 주인공들이 왜 적대하는지, 최종 보스, 결말, 톤
    - 참고 : 고전 동화 원작은 저작권이 만료돼 자유롭게 쓸 수 있으나,
      특정 애니메이션 회사의 캐릭터 디자인을 닮게 그리면 안 됨
