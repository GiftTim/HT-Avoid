    이 사이클을 여러 번 반복 → 최종적으로 "보스" 스테이지까지 도달해 클리어

f. 각 파트가 담당하는 역할
================================================================

  VN         : 서사 전달, 캐릭터 관계 형성, 다음 구간의 동기 부여
               (기존 엔진 그대로 사용 — 대사/커맨드/캐릭터/그래픽/오디오)

  피하기     : 순간적인 텐션/액션 담당. 플레이어는 이동으로 탄막을
               회피하고 공격으로 대응하며 클리어 조건(g절)을 달성하는
               것이 목표. 결과
               (클리어/실패, 생존 시간, 피격 횟수 등)가 다음 VN 파트의
               분기(대사/호감도/스토리 전개)에 반영되도록 설계
               (VariableStore를 통해 VN 쪽 조건문과 연결, h절 참고)

  최종 스테이지(보스) : 사이클의 마지막 관문. 일반 스테이지보다
               탄막 패턴/페이즈가 훨씬 복잡한 스테이지. 공격이 부활했으므로
               보스를 "쓰러뜨리는" 형태인지 "끝까지 버티는" 형태인지는
               미정 (클리어 조건은 g절/k절 참고)

g. 구현 시 필요한 신규 시스템
================================================================

  1. 피하기(Avoid) 미니게임 엔진 (회피 + 공격, 26.09.20 공격 부활)
     - 회피 : 플레이어 이동/충돌(피격) 판정, 탄막/공격 패턴 스폰
       (밈피하기 기반)
     - 조작 : 마우스 없이 키보드만 사용 (확정 26.09.20, 26.09.27 갱신)
       · 이동 : 방향키 왼쪽/오른쪽
       · 점프 : Alt (메이플 스토리식 — 기존 Space에서 변경)
       · 공격 : Ctrl (메이플 스토리식 — 기존 마우스 왼쪽 버튼에서 변경)
       · 조준 없음 : 공격 방향은 고정 (조준 조작 삭제, 26.09.27)
       · 이유 : 마우스가 필요 없어야 해외 유저가 콘솔(게임패드)로도
         플레이할 수 있음. 메이플 스토리와 동일한 방향키+버튼 구성이라
         직관적이고 게임패드(십자키 + 버튼)에 그대로 대응됨
       · 이 결정으로 플레이어 공격이 부활함 (26.09.19 "공격 삭제"
         번복, k절 참고). 기존 마우스 조준/공격 코드(AimCursor/
         PlayerAttack)를 키보드 전용으로 개조해서 사용
       · 현재 구현 (AvoidInput.inputactions / 코드) :
         Move = A/D 1D Axis, Jump = Space, Attack = 마우스 왼쪽 버튼,
         조준 = AimCursor(마우스 커서 추종) + PlayerAttack 이
         Mouse.current 위치로 방향 계산. 게임패드 바인딩은 없음
       · 바꿔야 할 것 : (1) Move 바인딩을 A/D → 방향키 좌우로,
         (2) Jump 바인딩을 Space → Alt 로, (3) Attack 바인딩을
         마우스 → Ctrl 로, (4) AimCursor(마우스 추종) 및 조준 시스템
         제거, (5) PlayerAttack 의 TryGetAimWorldPoint(마우스)를
         고정 방향 기반으로 교체,
         (6) 게임패드 바인딩(십자키 + 공격/점프 버튼) 병행 추가
     - 클리어 조건 : 미정 (공격 부활로 재검토 필요, 26.09.20)
       · 후보 : 일정 시간 생존 (26.09.19 잠정안, 밈피하기와 가장 가까움)
         / 보스(적) 처치 / 시간 생존 + 처치 병행 / 목표 지점 도달 등
     - 실패/재도전 처리 : 미정 (k절 참고)
       · 후보 : 헬테이커식 즉시 재도전 / 목숨 3개 / 대기방 / 보스 HP
         유지 (공격이 돌아왔으므로 "HP 유지"도 다시 의미가 생김 —
         원안은 보관본 참고)
     - 난이도 확대 : 사이클이 진행될수록 탄막 패턴/규모 확대
     - 신규 폴더 : Assets/Scripts/Avoid/ (이미 2단계에서 생성됨)

  2. 사이클 매니저 (GameCycleManager 가칭)
     - VN → 피하기 → VN 순서로 씬/상태를 전환하는 상위 컨트롤러
     - 피하기 결과값을 다음 VN 파트로 전달하는 역할
     - 신규 폴더 제안 : Assets/Scripts/Core/GameFlow/ (또는 프로젝트 루트 Core)

================================================================
h. 기존 VN 엔진과의 연동 지점
================================================================

  - 씬 레벨 연결 방식 : 애디티브 씬 로딩 (확정, 26.09.14)
    · VN 씬(VisualNovel.unity)을 언로드하지 않은 채 미니게임 씬(예:
      Avoid.unity)을 SceneManager.LoadSceneAsync(씬명, LoadSceneMode.
      Additive)로 위에 얹는 방식
    · 채택 이유 : DialogueSystem/CharacterManager/HistoryManager/
      VariableStore 등 VN 핵심 싱글톤이 DontDestroyOnLoad 처리가 안
      되어 있어서(AudioManager만 예외) 단일 모드 LoadScene으로 씬을
      완전 교체하면 전부 파괴됨. 같은 씬 안에서 오브젝트 SetActive
      토글하는 대안도 있었으나 콘텐츠가 한 씬에 계속 쌓여
      비대해지는 문제가 있어 기각
    · 주의 : 애디티브 로딩 시 VN 배경/그래픽 패널이 미니게임 씬 뒤에
      그대로 남아있으므로, 미니게임 씬 카메라의 Depth를 VN 카메라보다
      높게, Clear Flags를 Solid Color(또는 Depth Only)로 설정해 가려야
      함 (에디터 작업)
    · 상세 설계 : Assets/Docs/2. ChangePlan/[26.09.14_20.24] 피하기
      게임 기초 구조 및 VN 연결.txt 참고
  - VN 복귀 트리거 (26.09.20 갱신) : 현재는 Enemy 처치 시 VN으로
    복귀하도록 연결돼 있음 (26.09.17). 26.09.19 에는 공격 삭제로
    "클리어 조건 달성 시 VN 복귀"로 바꾸려 했으나 공격이 부활했으므로,
    클리어 조건(g절)이 확정된 뒤에 유지/교체를 결정 (3단계에서 처리)
  - VariableStore : 피하기 결과값(클리어/실패, 생존 시간, 피격 횟수 등)을
    변수로 저장 → VN의 LL_Condition이 이 변수를 읽어 대사 분기에 반영
    (예: "피하기 실패 시 다른 대사")
  - CommandManager : 대사 중 [startAvoid(스테이지명)] 같은 커맨드로
    미니게임 씬/모드 진입 (애디티브 로딩 사용)
  - VNGameSave : 사이클 진행도(몇 번째 사이클, 클리어 기록 등)도
    함께 저장해야 함 → 기존 세이브 데이터 구조 확장 필요
  - 자동저장 체크포인트 : 실패 처리 방식(g절)이 정해진 뒤 필요 여부 재검토.

    재개 — 즉시 재도전 방식으로 가면 불필요)

    지금까지는 적이 플레이어를 공격하지 않는 상태. "밈피하기" 기반 탄막

  □ 3-d. 패턴/페이즈 구성으로 마무리
    a~c 조합 위에 여러 패턴을 시간 경과(페이즈)별로 배치해 "마지막 보스
    스테이지"다운 콘텐츠 완성 → 3단계 목표 달성

      하려는 목적 (g절 참고)

      순수 회피"를 번복. 조작이 공격 전제(키보드 공격 + 상하 조준)라
      "공격 부활(A)"과 "순수 회피 유지(B)" 중 (A)를 선택함. 카드/RPG 는
      계속 폐기. 이에 따라 d·e·f·g·h·i·j절 문구를 "회피 + 공격"으로
      고쳤음
    - 공격 부활로 다시 정해야 하는 것 (미정)
      · 클리어 조건 (생존 시간 / 보스 처치 / 병행) — 위 미정 목록 참고
      · 보스 HP 개념과 승리조건 (보관본에 원안 있음)
      · 실패/재도전 방식 (보스 HP 유지·목숨제도 다시 후보가 됨)

    - 이로 인해 새로 생기는 확인 사항
      · 이동 축 : 현재는 좌우 + Alt 점프(중력 있는 횡스크롤형). 조준
        삭제(26.09.27)로 상하 방향키가 비었으므로, 메이플 스토리처럼
        상하 방향키를 사다리/플랫폼 이동 등에 쓸지, 또는 그냥 좌우
