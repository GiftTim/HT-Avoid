a. 확정 컨셉 (26.10.15)
================================================================

  프로젝트명 "HT-Avoid" = Helltaker(HT) + Avoid(피하기).
  ※ 이름의 "Avoid"는 처음 컨셉(피하기)의 흔적이다. 게임 파트는 이제
    리듬 게임이므로 프로젝트명/폴더명을 바꿀지는 미정 (j절).

  1. 기본 축 : 헬테이커 + 리듬 퀘스트 (확정)
     - 헬테이커의 "퍼즐 한 판" 자리에 "리듬 퀘스트식 리듬 한 판"이 들어감
  2. 스토리 컨셉 : 동화나라 (확정)
     - 동화의 주인공들이 적(= 그 판의 보스)이고, 플레이어는 그 동화
       세계를 헤쳐 나아간다. 챕터 1개 = 동화 1편, 그 주인공 = 그 판의
       보스 → 클리어 후 동료
  3. 조작 : 키보드와 게임패드 전용 (확정). 마우스 없음
     - 키보드 : 점프 F / 공격 J (확정 26.10.15)
     - 게임패드 : 점프 A(플스 ×) / 공격 X(플스 □) (확정 26.10.15 23:01)
  4. 게임 방식 : 비주얼 노벨 → 리듬 퀘스트(카피) → 비주얼 노벨 을 1세트
     (= 1챕터)로 진행 (확정)
  5. 리듬 퀘스트와 다른 점 (확정)
     - 장애물이 아니라 화면 오른쪽에 보스가 있고, 보스가 던지는 탄환을
       피하거나 공격해서 반격하는 방식
  6. 보스는 곡이 끝날 때까지 죽지 않는다 (확정)
     - 곡이 끝나면 울거나 도망가는 모션으로 한 판이 끝난다
     - 즉 "보스 처치"가 아니라 "곡 완주"가 클리어 조건이며, 보스 HP 는
       없다

  [ 헬테이커에서 가져오는 것 ]
  - 실패 시 그 판만 즉시 재도전
  - 챕터마다 새 캐릭터 1명을 동료로 (그 캐릭터 = 그 판의 보스)
  - 짧은 분량 (챕터 8~10개, 1~2시간)
  - 일직선 진행 (호감도/분기 없음, 결과에 따라 대사 몇 줄만 변화)
  - 대화 선택지 오답 → 리듬 판으로 되돌아감 (헬테이커의 즉사와 다름).
    다시 깬 뒤 그 대화를 처음부터 다시 봄

  [ 리듬 퀘스트에서 가져오는 것 ]
  - "규칙과 구조"만 가져온다 (횡스크롤 자동 달리기, 점프/공격 2버튼,
    박자에 맞춘 입력, 곡 = 레벨). 그림/음악/레벨 데이터는 직접 만든다
    (저작권). 세부는 c절

b. 게임 사이클 구조
================================================================

    ┌─────┐       ┌─────────────┐       ┌────┐
    │ VN  │ ──▶ │ 리듬 한 판    │ ──▶ │ VN │
    │     │      │ (곡 1곡)      │      │    │
    └─────┘       └─────────────┘       └────┘
        ▲            ▲   │ 실패             │ 선택지 오답
        │            └───┘ (즉시 재도전)    │
        │            ▲                      │
        │            └──────────────────────┘ (리듬 판으로 되돌아감)
        │                                   │ 정답
        └────── (다음 챕터로 반복) ─────────┘

    1챕터 = 1세트. 챕터 8~10개를 반복 → 마지막 보스 스테이지 클리어
    (챕터가 진행될수록 곡/탄환 패턴의 난이도와 규모가 확대됨)

  [ 1세트(1챕터) 흐름 ]
    1. VN    : 상황 설명, 그 챕터의 새 캐릭터(= 보스) 등장, 도입부
    2. 리듬  : 보스가 오른쪽에서 탄환을 던지고, 플레이어는 박자에 맞춰
               피하거나(점프) 공격해 반격하며 곡 끝까지 달린다.
               실패하면 그 판만 즉시 재도전. 곡이 끝나면 보스가 울거나
               도망가는 모션으로 끝남 = 클리어
    3. VN    : 클리어 후 대화 + 선택지. 정답이면 보스가 동료가 되고
               다음 챕터로. 오답이면 2번으로 되돌아가고, 다시 깬 뒤 이
               대화를 처음부터 다시 봄

  [ 각 파트의 역할 ]
  - VN   : 서사 전달, 캐릭터와의 관계 형성(동료 영입), 동기 부여
           (기존 엔진 그대로 — 대사/커맨드/캐릭터/그래픽/오디오)
  - 리듬 : 순간적인 텐션/액션 담당. 결과(실패 횟수, 놓친 탄환 수 등)는
           다음 VN 의 대사 몇 줄을 바꾸는 정도로만 반영
           (VariableStore 로 VN 조건문과 연결, g절)
  - 마지막 보스 스테이지 : 일반 챕터보다 곡/패턴이 복잡한 판. 클리어
           방식은 같음 (곡 완주)

c. 리듬 파트 규칙 (Rhythm Quest 카피 + 보스 탄환 방식)
================================================================

  [ 참고 : Rhythm Quest (ddrkirby) — 규칙 요약 ]
  - 횡스크롤 자동 달리기. 박자에 맞춰 버튼 2개(점프/공격)만 누른다
  - 장애물마다 필요한 입력이 다르다 : 구덩이/가시 = 점프, 지상 적 =
    공격, 공중 적 = 점프 후 공격, 여러 번 맞는 적 = 연속 공격
  - 공중 점프(날개), 점프 길게 누르기(비행 구간), 속도 구간 등은 월드가
    진행되며 추가됨
  - 실패 시 체력 없이 마지막 체크포인트로 돌아가고 음악도 되감김
  - 입력 지연(latency) 보정 옵션이 있음
  - 공개 설명 기준이므로 직접 플레이로 확인하며 보정할 것

  [ 이 프로젝트의 변형 (26.10.15 확정) ]
  - 화면 오른쪽에 보스가 있다. 보스는 곡 내내 살아 있고, 곡의 박자에
    맞춰 탄환을 던진다
  - 탄환이 "장애물"의 역할이다. 플레이어는 각 탄환에 대해
    · 피하거나(점프),
    · 공격해서 반격한다
  - 보스는 죽지 않는다. 곡이 끝나면 울거나 도망가는 모션으로 끝
  - 즉 Rhythm Quest 의 "바닥에 놓인 장애물"이 "보스가 던지는 탄환"으로
    바뀌고, 지형(구덩이)이 아니라 보스와 탄환이 한 판의 중심이다

  [ 확정된 것 ]
  1. 입력 : 점프 F / 공격 J 2버튼 (키보드 + 게임패드). 마우스 없음.
     방향키 이동·전진 키 없음 (패드 버튼 배정은 미정)
  2. 진행 : 자동으로 달리며 박자에 맞춰 입력
  3. 클리어 : 곡을 끝까지 완주 (보스 처치 아님)
  4. 탄환은 2종류 (확정 26.10.15)
     - 회피 탄환 : 피해야 하는 공격 (점프 F)
     - 반격 탄환 : 쳐내서 반격할 수 있는 탄환 (공격 J)
     - 각 탄환에 맞는 입력(피하기 / 공격하기)을 박자에 맞는 타이밍에
       눌러야 한다. 타이밍은 곡의 박자 기준 (판정 오차 범위는 j절)
  5. 반격의 결과 : 연출 + 점수 + 피버 게이지 (확정 26.10.15)
     - 반격 성공 시 보스가 맞는 연출이 나오고 점수가 오르며 피버
       게이지가 찬다. 보스는 죽지 않으므로 클리어 조건과는 무관
     - 피버 게이지가 찼을 때 무슨 일이 생기는지는 j절
  6. 실패 규칙 : HP 방식 (확정 26.10.15). HP / 피버 / 점수는 전부
     뮤즈 대쉬(Muse Dash)를 기준으로 한다 (확정 26.10.15)
     - 탄환을 못 피하거나 놓치면 HP 가 깎이고, HP 가 0 이 되면 실패 →
       그 판만 즉시 재도전 (헬테이커식). 체력(하트)을 쓰지 않던 3D
       피하기 때의 규칙과 달라진 점
     - HP 수치/피해량/회복 여부는 j절 (※ 뮤즈 대쉬의 구체 수치는 이
       문서에서 확인하지 못함 — 직접 플레이로 확인하며 맞출 것)
  7. 탄환 겹침 패턴 허용 (확정 26.10.15)
     - 같은 박에 회피 탄환과 반격 탄환이 겹쳐 나오는 패턴을 쓴다.
       이때 F 와 J 를 동시에 눌러야 하는 구조가 된다 (판정 방식은 j절)
  8. 연타 노트 : 도입 확정 (26.10.15, J 키). 세부는 아래 [리듬 수치 규칙]
  9. 음악은 임시 곡으로 뼈대부터 만들고 나중에 교체


  [ 리듬 수치 규칙 (확정 26.10.15 22:52 — 뮤즈 대쉬 기준으로 가져옴) ]

  ■ 판정
  - 반격 탄환(J) : PERFECT ±50ms / GREAT ±130ms / 그 밖 MISS
    (수치는 플레이 테스트 후 조정 가능)
  - 회피 탄환(F) : PASS / MISS 2단계만 (PERFECT 개념 없음)
  - 헛공격(J 를 아무 데나 침) : 페널티 없음. 콤보도 안 끊김
  - 입력 오프셋 : judgeTime = noteTime + userOffset (옵션 슬라이더)
    Early 가 많이 뜨면 오프셋 -, Late 가 많이 뜨면 +

  ■ HP (서바이벌 게이지)
  - 최대 HP 고정, 시작은 최대치. HP 0 → 그 판 즉시 재도전
  - 기본 캐릭터 최대 HP 300 (확정 26.10.15 23:01). 피해 소/중/대 =
    20/30/40 (소형만 15번 맞으면 실패). 하트 회복량 +60 (확정 23:07)
  - 감소 : 탄환에 맞을 때만. 반격 탄환을 J 로 쳐내지도 F 로 피하지도
    못하면 피격 → HP 감소
  - 반격 탄환을 F 로 피해서 그냥 지나가게 두면 HP 는 그대로, 점수와
    정확도만 감점 (HP 와 분리)
  - 회복 : 하트 도입. 노트를 처리해도 회복되지 않음. 만피일 때 하트를
    먹으면 회복 대신 점수 보너스 +300 (확정 23:07)
  - 하트 / 파란 음표 같은 수집물은 판정선에 닿으면 자동 처리 (판정 표시 없음)

  ■ 탄환 크기 등급 (도입 확정)
  - 소 / 중 / 대 등급을 두고 점수·피버 충전·피해를 한 축으로 묶음.
    (뮤즈 대쉬 참고 : 피해 20/30/40/50, 점수 200/300/400/500)
  - 피해 20/30/40, 기본 점수 200/300/400 확정 (23:07). 피버 충전량은
    위 [피버] 항목 기준 (소 1 / 대 2)

  ■ 피버
  - 충전 60 도달 시 발동, 5초 지속, 자동 발동만 (수동 피버 없음)
  - 충전량 (60 기준) : 소형 / 튀어나오는 적 / 유령 / 보스 원거리·근거리
    공격 = 1, 대형 / 복선 궤도 / 망치 / 연타 / 악보(롱노트) = 2
  - PERFECT = 풀 충전, GREAT = 절반
  - 피버 중에는 노트를 칠 때마다 점수 +50% (배율 1.5)
  - 피버 중 배경 변화 연출 (동화 장면이 바뀌는 식)

  ■ 연타 노트 (J 키)
  - 패턴이 나오는 동안 J 를 연타. 구간 길이에 비례한 일정 속도 이상으로
    입력해야 통과
  - 요구 속도보다 느리면 HP 피해 + 콤보 끊김
  - 최대 타수 상한을 둠 (무한 점수 방지)
  - 점수 (타수 × 20) + 200, 콤보/피버 보너스는 없음

  ■ 정확도 / 랭크
  - 정확도(%) = (PERFECT + GREAT×0.5 + PASS) / 총 노트 수 × 100
    (수집물 포함 총 노트 수, 자동 처리 항목은 PERFECT 로 간주)
  - 랭크 4단계 : S / A / B / C (구간 수치는 PoC 때 정함)
  - 풀 콤보 시 정확도와 관계없이 A 이상 보장
  - 랭크는 진행에 영향 없음. VN 대사 몇 줄만 변화 (VariableStore 연동)

f. 구현 방향 (리듬 파트 시스템)
================================================================

  [ 26.10.14 합의 사항 — 그대로 유효 ]
  1. 물리를 쓰지 않는다
     - 모든 진행의 기준은 "노래 재생 시간" 하나. 캐릭터/맵/보스/탄환은
       그 시간에 맞춰 정해진 위치에 그려지기만 한다
     - 플레이어 x = 노래 시간 × 속도. 점프 = 박자 단위로 고정된 시간
       기반 포물선 (중력 없음). 판정 = 입력 시각과 노트 시각의 차이
       (충돌 판정 아님)
     - Tilemap Collider 2D / Rigidbody2D 는 쓰지 않음. 타일맵은 그림 전용
     - 이유 : 물리는 프레임마다 결과가 달라 박자와 어긋나기 쉬움
  2. 리듬 곡 재생은 VN AudioManager 와 따로 둔다
     - Assets/Scripts/Rythm/ 에 전용 재생기(RhythmConductor 가칭). Rythm
       씬 안의 AudioSource 하나, PlayScheduled + AudioSettings.dspTime
       으로 시작/현재 시간 계산. 다른 스크립트는 이 시계만 본다
     - VN 의 AudioTrack 은 AudioSource 가 private 이라 재생 시간을 못
       읽고 BGM 용 기본값(즉시 재생/페이드/loop)이 박자 동기화에 안 맞음
     - 공유 : Music 믹서 그룹(설정창 볼륨 적용), 효과음은 AudioManager.
       PlaySoundEffect. 리듬 판 진입 시 VN BGM 은 StopTrack, 복귀 후
       대본에서 다시 재생
  3. 타일맵 : 바닥은 채보를 보고 코드로 칠하는 것을 권장
     (Tilemap.SetTile). 손으로 칠하는 것은 장식 타일맵만
  4. 씬 구조 : 게임 오브젝트/카메라는 Canvas 밖, Canvas 는 UI 전용.
     2D 앞뒤 순서는 z 가 아니라 Sorting Layer 로. 크기 조절은 Scale 이
     아니라 카메라 size 로

  [ 26.10.15 추가 — 보스/탄환 ]
  1. 보스는 화면(카메라) 기준 오른쪽에 고정해 둔다
     - 플레이어는 자동으로 달리지만 카메라가 따라가므로 보스는 항상
       같은 화면 위치에 있는 것으로 처리 (권장). 월드에 서 있는 보스를
       플레이어가 향해 달리는 방식은 아님 — 미정이면 j절에서 확정
  2. 탄환 = 채보의 노트
     - 탄환 하나 = [박 번호, 종류] 데이터 한 건. 보스는 그 박의 "던지는
       시각" 보다 일정 박 앞서 던지는 연출을 시작하고, 탄환은 플레이어
       위치에 노트 시각에 맞춰 도착
     - 탄환 비행도 물리가 아니라 "던진 시각 → 도착 시각" 사이의 보간
  3. 보스 상태는 연출용 상태기계
     - Idle/Throw/Hit(반격 맞음)/곡 종료 시 Cry 또는 Flee. HP 없음
  4. 곡 끝 처리 : 마지막 노트 이후 음악이 끝나면 보스 종료 모션 →
     클리어 확정 → AvoidSession 계열 결과 기록 → VN 복귀

  [ 필요한 시스템 — PoC 필수 ]
    1. 음악 시계 (RhythmConductor) : dspTime, BPM, 시작 오프셋 → 현재 박
    2. 자동 달리기 + 카메라 추적
    3. 입력 + 판정 : 점프 F / 공격 J 2버튼(키보드+패드), 오차 범위로 판정
    4. 시간 기반 점프 곡선
    5. 보스(오른쪽 고정, 던지기 연출) + 탄환 2종 (회피 탄환 = F /
       반격 탄환 = J)
    6. 채보 데이터 : BPM, 오프셋, [박 번호, 탄환 종류] 목록
       (ScriptableObject — StageProfile 방식의 연장)
    7. 채보 → 탄환 배치기 (박 시간 기준)
    8. HP + 실패 → 재시작 (HP 0 이면 실패, PoC 는 곡 처음부터가 간단)
       점수 / 피버 게이지(반격 성공 시 상승)는 UI 만이라도 PoC 에 포함
    9. 곡 끝 = 보스 종료 모션 + 클리어 → VariableStore 기록 → VN 복귀

  [ PoC 이후 ]
    공중 점프, 길게 누르기, 연속 타격 탄환, 속도 구간, 지연 보정 화면,

    보정), 체크포인트 복귀

g. VN 엔진과의 연동 지점
================================================================

  - 씬 연결 방식 : 애디티브 씬 로딩 (확정 26.09.14)
    · VN 씬(VisualNovel.unity)을 언로드하지 않고 게임 씬을 Additive 로
      얹는다. VN 핵심 싱글톤(DialogueSystem/CharacterManager/
      HistoryManager/VariableStore)이 DontDestroyOnLoad 가 아니라서
      Single 모드로 바꾸면 파괴되기 때문
    · 게임 씬 카메라의 Depth 를 VN 카메라보다 높게, Clear Flags 를
      Solid Color(또는 Depth Only)로 해 VN 배경을 가릴 것
  - 진입/복귀 커맨드 : 기존 [wait]startAvoid(스테이지명) 이 씬을 얹고
    종료 플래그(AvoidSession.IsFinished)가 될 때까지 기다린 뒤 결과를
    변수로 쓰고 VN 으로 복귀. 리듬 씬도 같은 흐름을 쓴다
    · 커맨드 이름(startAvoid)을 리듬에 맞춰 바꿀지는 j절
  - 선택지 오답 → 리듬 재진입 : 오답 결과 줄에 [wait]startAvoid() 다음
    줄에 [wait]restartDialogue() 를 쓰면 그 대본을 첫 줄부터 다시
    재생. "클리어 후 대화"는 도입부와 별도 파일로 두고 도입 파일 끝에서
    load(-f 경로)로 이어 붙임 (예 : Test/AvoidChapterTest.txt →
    _After.txt). 한계 : 선택지 한 단계만 확인, 중첩 선택지 미확인
  - VariableStore : 리듬 결과(실패 횟수, 놓친 탄환 수 등)를 변수로 저장
    → LL_Condition 이 읽어 대사 몇 줄을 바꿈. 현재 키는 $Avoid.hitCount /
    retryCount / remainingTime / cleared. 리듬에서는 remainingTime 이
    의미 없으므로 키 구성을 다시 정해야 함 (j절)
  - VNGameSave : 챕터 진행도(몇 번째 챕터, 클리어 기록)도 저장 →
    세이브 데이터 구조 확장 필요
  - 자동저장 체크포인트 : 불필요 (즉시 재도전). 저장은 챕터 단위 진행도만

    (확정 26.10.15 : 키 F/J, 탄환 2종, 반격 = 연출+점수+피버, 실패 = HP
     → c절 참고. 아래는 그 세부)
    (확정 26.10.15 : HP / 피버 / 점수는 뮤즈 대쉬 기준, 겹침 패턴 허용)
    (확정 26.10.15 22:52 : 판정 / HP / 피버 / 연타 / 정확도 / 랭크 규칙
     → c절 [리듬 수치 규칙]. 아래는 그 세부와 남은 것)
    - 수치 미정 : 하트 등장 빈도, 랭크 구간 정확도 수치
    - 연타 노트 세부 : 구간 길이별 필요 타수(요구 속도), 최대 타수 상한
    - 겹침 패턴 세부 : F/J 동시 입력을 허용 오차 몇 ms 안에서 "동시"로
      볼지, 둘 중 하나만 맞췄을 때 판정 / 피해 처리
    - 클리어 기준 : 곡 완주만 (확정). 정확도/랭크는 기록용 + 대사 변화
    - 한 판 길이(곡 길이), 챕터당 곡 수. 곡이 짧으면 피버 5초 조정
    - 지연 보정 UI

  ■ 연출 / 구조
    - 보스를 화면 고정으로 둘지 월드 고정으로 둘지 (f절 권장 = 화면 고정)
    - 보스 종료 모션 구성(울기/도망 중 챕터별로 다르게 할지)
    - 곡 제작/조달 : 임시 곡(BPM 일정한 프리 라이선스)부터, 최종 곡의
      출처(직접 작곡/의뢰/라이선스)
    - 채보 작성 방식 : PoC 는 ScriptableObject 에 박 번호 직접 입력.
      이후 에디터 툴이 필요한지

  ■ 정리 / 이름
    - 3D 피하기 코드 처리(삭제/보관/그대로) 시점
    - 프로젝트명 "HT-Avoid" / 폴더 Avoid / 커맨드 startAvoid /
      변수 $Avoid.* 이름을 리듬에 맞게 바꿀지
    - 결과 변수 키 구성 (실패 횟수, 놓친 탄환 수, 클리어 여부 등)
    - 리듬 PoC 기한 (새로 정하지 않음)

  ■ 스토리
    - 확정 : 동화나라, 동화의 주인공 = 그 판의 보스 = 동료
    - 미정 : 플레이어(주인공)가 누구이고 왜 동화 세계를 지나가는지
    - 미정 : 챕터별 동화/보스 캐릭터(챕터 수와 함께). 캐릭터마다 탄환
      종류와 던지는 연출, 곡 분위기를 원작 소품에서 따서 정함
    - 미정 : 동화 주인공들이 왜 적대하는지, 최종 보스, 결말, 톤

  ■ 기타
    - 콘솔 "출시"가 목표인지 PC 에서 패드 지원 정도인지 (현재는 "입력을
      키보드/패드로만 설계"하는 범위)
    - 챕터 수와 마지막 보스 스테이지 구성
    - 선택지가 여러 번 나오는 챕터에서 오답 재진입을 매번 적용할지
    - ES3 세이브 실사용 테스트 시점 (저장 데이터가 생기는 시점)
    - LL_Choice 는 선택 결과를 변수로 자동 기록하지 않음 (작가가 결과
      줄에 대입 커맨드를 적어야 함) — 콘텐츠가 늘면 자동화 검토
