[이번에 내린 설계 결정과 이유]

  1. SoundController 는 만들지 않음
     - 0919 에 AudioManager 를 게임 전체의 유일한 오디오 창구로 확정함
       (Record [26.09.19_15.12]). 원본 SoundController 는 로컬
       AudioSource 를 쓰므로 믹서 그룹을 우회하고 재생 경로가 이원화됨
       → PlayerHP 가 AudioManager 로 직접 재생. 클립 배열이 아니라
       hitClip 하나 (원본도 index 0 만 썼음)
  2. UIController 에 GameStart/GameOver 추가
     - 원본 GameController 가 uiController.GameStart()/GameOver() 를
       호출하는데 원본 UIController 에는 그 메서드가 없음 → 원본 그대로
       복사하면 컴파일 에러. 튜토리얼 스냅샷 시점 차이로 보임
  3. PlayerHP 는 SpriteRenderer 를 Inspector 지정 방식으로
     - Avoid.unity 의 Player 루트에는 SpriteRenderer 가 없음. 자식
       Body 와 AttackEffect 에만 있음 (원본의 GetComponent 는
       NullReference). GetComponentInChildren 은 AttackEffect 를 잡을
       수 있어 쓰지 않음
  4. 피격 태그는 CompareTag 대신 문자열 비교
     - ProjectSettings/TagManager 에 Obstacle 태그가 아직 없음
       (Interaction_NPC, Interaction_Item 만 있음). CompareTag 는
       미등록 태그면 예외를 던지므로 tag != "Obstacle" 로 비교
  5. 사망 시 처리는 "패턴 정지 + 게임오버 패널"까지만
     - 재도전 / 목숨제 / VN 복귀 / 클리어 조건은 Plan 문서에서 미정
       (3-c, 실패 시 처리 즉시 재도전 vs 목숨제 vs 게임오버). 정해지지
       않은 정책은 구현하지 않음
