       오디오 AudioManager 통합 리팩터링.txt (a~h 형식)
     - 조사한 것 : Pattern01.cs, AudioManager.cs, Avoid.unity 의
       Pattern01 오브젝트(AudioSource 설정), VisualNovel.unity 의
       AudioManager 믹서 연결(music/sfx/voices 3개), CMD_
       DatabaseExtension_Avoid.cs(씬 로드/언로드 흐름), Avoid 폴더
       전체에서의 오디오 사용처(Pattern01 뿐)
     - 문제점 3가지 정리 : (1) Voice 믹서 그룹 우회, (2) 오디오 재생
       경로 이원화(VN=AudioManager / Avoid=로컬 AudioSource),
       (3) 클립이 AudioSource 컴포넌트에 걸려 있어 코드만 봐서는
       무슨 소리인지 알 수 없음
     - 이전 Record 초안(PlayVoice("Audio/Voices/...") 문자열 경로)에서
       바뀐 설계 결정 :
       · 클립 지정 : 문자열 경로 대신 [SerializeField] AudioClip 사용.
         PlayVoice(string)은 호출마다 Resources.Load 를 하는데 이
         코드는 0.1초마다 재생 여부를 검사하므로, 경로 오타/파일명
         변경(현재 한글 파일명) 시 LogError 가 쏟아질 수 있음
       · 반복 재생 : loop:true 한 번 호출 대신 기존과 같은
         "끝나면 다시 재생" 폴링 유지. loop 로 만든 SFX 오브젝트는
         AudioManager 가 자동 삭제를 예약하지 않아, 정리 코드가 못
         돌면 DontDestroyOnLoad 아래에 영구 잔류할 위험이 있음
         (폴링 방식은 클립 길이 + 1초 뒤 자동 정리되는 fail-safe)
       · 정지 : AudioManager.StopSoundEffect(이름) 대신 Pattern01 이
         자기 소스 참조를 들고 OnDisable 에서 직접 Destroy
     - 발견한 핵심 위험 : AudioManager 의 SFX 오브젝트는
       DontDestroyOnLoad 이므로 Avoid 씬이 언로드되어도 안 사라짐.
       OnDisable 정리 코드가 없으면 VN 복귀 후에도 음성이 끝까지
       계속 들림 (로컬 AudioSource 시절엔 없던 새 문제)
     - 또 다른 위험 : AudioManager 는 재생 종료 1초 뒤에 오브젝트를
       파괴하므로 voiceSource 는 null 체크가 isPlaying 보다 먼저여야
       함 (MissingReferenceException 방지)

  2. 설계 확인 질의응답 : "VN AudioManager 를 메인으로 가는 거냐"
     - 답 : 그렇다. 기존 AudioManager(클래스명은 VNAudioManager 가
       아니라 그냥 AudioManager, Assets/Scripts/VisualNovel/Core/
       Audio/)를 게임 전체의 유일한 오디오 창구로 쓰는 방향.
       DontDestroyOnLoad 싱글톤 + Avoid 가 VN 위에 Additive 로 얹히는
       구조라 성립
     - 주의 : AudioManager 오브젝트가 VisualNovel.unity 안에만 있어서
       Avoid 씬 단독 Play 시 AudioManager.instance == null. Avoid.unity
       에는 AudioListener 도 없어 단독 Play 에선 원래 소리가 안 났음
       → 코드에서 instance null 이면 조용히 건너뛰고 스폰은 계속
     - 장기 옵션(이번 범위 밖) : Avoid 단독 테스트에서도 소리가 필요해
       지면 AudioManager 를 부트스트랩 씬/프리팹으로 분리
