b. 요구한 기능
================================================================

  VisualNovel Scene과 Avoid Scene을 애디티브 씬 로딩(LoadSceneMode.
  Additive)으로 연결해서 실제로 왔다갔다 전환해보고, 에디터 Play
  모드에서 직접 실행시켜 확인한다 (사용자 요청, 26.09.16).

  이번 범위는 "전환 매커니즘 자체"만 검증하는 것으로 한정함. 보스로
  등장할 characterKey / AvoidCharacterProfile / AvoidSceneController.
  Setup 같은 캐릭터 인터페이스 시스템은 포함하지 않음 (이미 Assets/
  Docs/2. ChangePlan/[26.09.14_20.24] 피하기 게임 기초 구조 및 VN
  연결.txt 에 설계되어 있으나 아직 미착수 상태 — h절 참고, 이번 검증이
  끝난 뒤 이어서 진행 예정)

  완료 조건 : 코드 작성으로 끝내지 않고, 에디터 Play 모드로 VN → Avoid
  → VN 왕복이 실제로 되는지 직접 실행해서 확인하는 것까지 포함

  [ 씬 파일 / 빌드 세팅 ]
  - Assets/Scenes/Avoid.unity 는 이미 존재함 (직전 세션 "피하기 게임
    기본 조작·공격 인터페이스" 작업에서 만들어짐)
  - (수정: 해결 확인됨) ProjectSettings/EditorBuildSettings.asset 를
    다시 열어보니 VisualNovel.unity(인덱스 0), Avoid.unity(인덱스 1)
    둘 다 이미 등록되어 있음. 커밋 로그상 6a3c62e("점프/그라운드 레이어
    버그 수정 + 리스폰 존 추가")에서 함께 등록된 것으로 보임 → 이 항목은

  [ 카메라 설정 ] (기존 문제 그대로 재확인됨 — 아직 미수정)
  - VisualNovel.unity 안 카메라 4개(Camera-Main/Camera - Live2D/
    Camera - Model3D/Camera-Overlay) 중 가장 높은 Depth는 0
    (Camera-Main만 Depth -1)
  - Avoid.unity 의 Camera-Main 은 Clear Flags = Skybox(1), Depth = -1
    → 지금 상태로 애디티브 로딩하면 VN 카메라들(Depth 0)이 나중에
    그려져서 Avoid 화면이 VN 화면에 가려짐
  - 두 씬 카메라 모두 AudioListener 컴포넌트를 갖고 있음 → 두 씬이
    동시에 열리면 AudioListener가 2개 동시 활성화되어 Unity가 경고를
    띄우고 오디오 출력이 불안정해짐

  [ 커맨드 시스템 ]
  - CMD_DatabaseExtension_Avoid.cs 는 여전히 없음 (재확인됨)
  - 참고할 기존 패턴 : CMD_DatabaseExtension_General.cs 의 "hideui"/
    "showui" 명령 — DialogueSystem.instance.Hide/Show(speed, immediate)
    를 Func<string[], IEnumerator> 로 등록해 코루틴 안에서 yield로
    대기하는 구조 (그대로 재사용 가능)
  - CommandDatabase.AddCommand(이름, 델리게이트) + 리플렉션 자동 스캔
    구조라 새 확장 클래스를 추가해도 수동 등록 불필요

  [ ★ 새로 발견 1 : 최초 초안의 대본 문법이 실제 파서 규칙과 안 맞음 ]
  - 최초 초안(01:49)에는 `narrator "..." [startAvoid]` 형태로 적었으나,
    실제 엔진 코드를 다시 확인해보니 이 표기는 동작하지 않음
  - DialogueParser.cs 의 commandRegexPattern
    (`[\w\[\]]*[^\s]\(`) 과 DL_COMMAND_DATA.cs 의 COMMAND_PATTERN
    (`([\w\.|\d+|\[|\]])*\(([^)]*)\),?`) 둘 다 여는 괄호 `(` 가 있어야
    "명령"으로 인식함 → 괄호 없는 `[startAvoid]`는 명령으로 파싱되지
    않음
  - 또한 ConversationManager.cs 의 LINE_RunCommands(195~219줄)를 보면,
    명령 이름이 `[wait]` 접두어를 달고 있거나 이름이 정확히 "wait"인
    경우에만 그 명령이 끝날 때까지 대기(yield)함. 그 외의 명령은
    fire-and-forget으로 실행하자마자 바로 다음 줄로 넘어가 버림
  - startAvoid/endAvoid는 씬 로드·언로드가 끝나야 다음 대사로 넘어가야
    하는 명령이므로, 대본에는 반드시 `[wait]startAvoid()` /
    `[wait]endAvoid()` 형태(괄호 필수 + wait 접두어 필수)로 써야 함

  [ ★ 새로 발견 2 : Space 키 입력 충돌 (기존 로드맵/문서에 없던 내용) ]
  - Assets/Input/VisualNovelInput.inputactions 의 "Next"(대사 진행)
    액션이 Keyboard의 Space, Enter 둘 다에 바인딩되어 있음
    (PlayerInputManager.cs 의 OnNext → DialogueSystem.OnUserPrompt_Next)
  - Assets/Input/AvoidInput.inputactions 의 "Jump" 액션도 Keyboard의
    Space에 바인딩되어 있음
  - VN 쪽 입력 리스너(PlayerInputManager)가 붙은 오브젝트는
    VisualNovel.unity 안에 있고, 이 씬은 애디티브 로딩 중에도 언로드
    되지 않으므로 Avoid 씬이 떠 있는 동안에도 계속 활성 상태임
  - 결과 : Avoid 씬에서 점프하려고 Space를 누르면, 그 순간 VN의
    "다음 대사" 입력도 동시에 발동되어 대화가 즉시 다음 줄
    (`[wait]endAvoid()`)로 넘어가 버림 → 점프를 테스트하려던 것뿐인데
    의도치 않게 피하기 화면이 꺼지는 것처럼 보일 수 있음
  - 이 충돌 자체를 지금 고칠지 여부는 e절 참고 (결론 : 이번 범위에서는
    고치지 않고, 테스트 방법으로 회피함)

  [ ★ 새로 발견 3 : Play 모드 진입 시 실제로 이 대본을 띄우는 방법 ]
  - VisualNovel.unity 안에는 TESTING.TestDialogueFiles 라는 기존 개발용
    컴포넌트가 있음 (Assets/Scripts/VisualNovel/Test/TestDialogueFiles.cs)
  - Start()에서 인스펙터에 지정된 TextAsset fileToRead 를 자동으로
    VNManager.instance.LoadFile()로 불러와 대화를 바로 시작시키는 구조
  - 현재는 fileToRead 가 testFile8.txt를 가리키고 있음 → 이번 테스트
    대본을 실제로 재생해 보려면 이 필드를 AvoidRoundTripTest 로
    바꿔야 함 (Play 모드 진입 = 씬 파일을 열고 Play 버튼을 누르는 것
    뿐이라, 대본을 실제로 로드하는 진입점은 이거 하나뿐임)
  - 이 값을 바꾸는 것 자체가 VisualNovel.unity 씬 파일 수정에 해당함
    → g절/h절에 "임시 변경, 테스트 후 원복 필요"로 명시

  [ Avoid 씬 안 오브젝트 ]

    있음, 계층 정리용 폴더)가 이미 있지만 스크립트는 아직 안 붙어있음
  - Avoid/Core 폴더에는 AimCursor/AvoidPlayerController/Enemy/

d. 요구한 기능을 만들기 위해서 어떤 식으로 생성하거나 변경해야 하는지
================================================================

  1) (완료됨, 손 안 댐) Build Settings 에 Avoid.unity 등록
     - c절에서 확인한 대로 이미 되어 있음 → 이번 작업에서 스킵

  2) (에디터) Avoid.unity 의 Camera-Main 설정 변경
     - Clear Flags : Skybox → Solid Color
     - Depth : -1 → 1 (VN 카메라 중 가장 높은 값 0보다 위로)
     - AudioListener 컴포넌트 제거 (VN 쪽 AudioListener 하나만 남김)

  3) 신규 파일 : Assets/Scripts/VisualNovel/Core/Commands/Database/
     Extensions/CMD_DatabaseExtension_Avoid.cs
     - CMD_DatabaseExtension 상속, "startAvoid"/"endAvoid" 명령 등록
       (Func<string[], IEnumerator>)
     - startAvoid(string[] data) : 인자 없이 동작
       1. DialogueSystem.instance.Hide(0f, true) 로 대화 UI 즉시 숨김
       2. yield return SceneManager.LoadSceneAsync("Avoid",
          LoadSceneMode.Additive)
       3. Debug.Log로 로드 완료 확인용 로그만 남김 (characterKey 기반
          Setup 호출은 이번 범위 밖)
     - endAvoid(string[] data) : 인자 없이 동작
       1. yield return SceneManager.UnloadSceneAsync("Avoid")
       2. DialogueSystem.instance.Show(0f, true) 로 대화 UI 복귀

  4) 신규 파일 : Assets/Resources/Dialogue Files/Test/
     AvoidRoundTripTest.txt (왕복 테스트 전용 대본)
     - (수정) 문법은 반드시 괄호 + wait 접두어를 갖춰야 함 (c절 새로
       발견 1 참고):
         narrator "피하기로 진입합니다" [wait]startAvoid()

         [wait]endAvoid()

         narrator "VN으로 복귀했습니다"
     - 중간 줄([wait]endAvoid())은 대사 없이 명령만 있는 줄이라, 첫
       줄에서 대사가 끝난 뒤 사용자가 입력(Enter 권장, h절 참고)으로
       진행시켜야 실행됨 → 이 지점에서 Avoid 씬을 직접 조작해보고,
       준비되면 입력해서 복귀

  5) (신규 단계, 실행 확인을 위해 반드시 필요) VisualNovel.unity 안
     TESTING.TestDialogueFiles 컴포넌트의 fileToRead 를 testFile8 →
     AvoidRoundTripTest 로 임시 변경
     - 테스트 종료 후 원래 값(또는 다른 필요한 파일)으로 되돌릴 것

  6) (실행) 에디터 Play 모드로 VisualNovel.unity 실행, 왕복 테스트
     - 확인 항목 : 대화 UI가 사라지는지 / Avoid 씬이 VN 화면 위에
       제대로 그려지는지(가려짐 없는지) / 플레이어 이동·공격이
       정상 동작하는지 (점프는 h절 이유로 이번엔 확인 생략) / Hierarchy에
       VisualNovel·Avoid 두 씬이 동시에 떠 있고 VN 싱글톤 오브젝트가
       파괴되지 않았는지
     - Enter 키로 복귀 진행 후 확인 항목 : Avoid 씬이 내려가는지 / 대화
       UI가 정상 복귀하는지 / 대사 진행 상태·VariableStore 값이
       유지되는지

e. 다른 방법들 중에서 왜 d의 방식으로 만든 것인지
================================================================

  씬 연결 방식 자체(애디티브 로딩)는 26.09.14에 이미 확정된 결정이라
  이번 문서에서 재검토하지 않음 (로드맵 h절 / [26.09.14_20.24] 문서
  e절 참고).

  [ characterKey/보스 프로필까지 이번에 같이 넣을지 여부 ]
  - 대안 1 : 26.09.14 설계대로 AvoidCharacterProfile/
    AvoidSceneController.Setup까지 한 번에 구현
    · 단점 : 사용자가 이번에 원한 건 "왔다갔다 되는지 실행해서 확인"
      인데, 범위를 넓히면 아직 안 만든 ScriptableObject 프로필 쪽에서
      막혀 정작 검증하려는 핵심(씬 전환 자체)을 못 볼 위험이 있음
      → 기각
  - 대안 2 (채택) : characterKey 없이 [wait]startAvoid()/[wait]endAvoid()
    만으로 순수 전환 매커니즘만 먼저 검증
    → 이번 세션에서 채택 (기존 결정 유지)

  [ AudioListener 2개 동시 활성화 문제 처리 ]
  - 대안 1 : 그냥 둔다 → 기각 (사운드 출력 지점 불명확해짐)
  - 대안 2 (채택) : Avoid 카메라의 AudioListener 컴포넌트 제거
    → 기존 결정 유지

  [ ★ Space 키 충돌(새로 발견) 을 지금 고칠지 여부 ]
  - 대안 1 : Input Actions 에셋을 리바인딩해서 충돌 자체를 해소
    (예: Avoid Jump를 다른 키로 변경, 또는 VN Next에서 Space 제거)
    · 단점 : 이번 문서의 범위는 "전환 매커니즘 검증"으로 한정하기로
      이미 정해져 있는데, 입력 바인딩 변경은 VN 대사 진행과 Avoid
      조작 두 시스템 모두에 영향을 주는 별도 결정이라 지금 끼워
      넣으면 범위가 또 넓어짐 → 기각
  - 대안 2 (채택) : 코드/에셋은 그대로 두고, 테스트할 때 점프 확인은
      생략하고 복귀는 Enter 키로 트리거해서 회피
    · 왕복 매커니즘 자체를 검증하는 데는 지장 없음
    · 근본적인 입력 충돌 해소는 다음 ChangePlan(보스/캐릭터 인터페이스
      작업, [26.09.14_20.24] 문서 이어서 진행할 때)에서 별도로 처리
    → 이번 세션에서 채택

  [ Play 모드에서 대본을 실제로 띄우는 방법 ]
  - 대안 1 : 이번 테스트 전용 새 MonoBehaviour/GameObject를 새로 만들어
    씬에 추가
    · 단점 : 이미 TESTING.TestDialogueFiles 라는 동일한 용도의 장치가
      씬에 존재하는데 중복으로 새로 만드는 건 불필요한 코드 추가 → 기각
  - 대안 2 (채택) : 기존 TestDialogueFiles.fileToRead 값만 임시로
    이번 테스트 파일로 바꿔서 재사용, 테스트 후 원복
    → 이번 세션에서 채택

    "Jump"가 둘 다 Space에 바인딩되어 있고, VN 입력 리스너는 Avoid

    끝나버릴 수 있음. 이번 테스트에서는 점프는 확인하지 말고, 복귀는
    Enter 키로 트리거할 것. 근본 해결은 이번 범위 밖 (e절 참고)
