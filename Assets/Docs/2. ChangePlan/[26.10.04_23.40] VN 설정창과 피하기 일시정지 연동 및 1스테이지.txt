b. 요구한 기능
================================================================

  10.05(내일) 목표 : UI + 1스테이지. UI 는 "VN 쪽에서 설정하는 것을
  기본으로" 한다 (26.10.04 사용자 결정).

  1. VN 씬에 설정창을 만든다 (VN 에서 열고 닫을 수 있음)
  2. 피하기 씬에서도 같은 설정창을 쓸 수 있게 한다
     - 피하기 중 일시정지 입력(Esc / 게임패드 Start) → 게임이 멈추고
       설정창이 열림 → 닫으면 이어서 진행
     - 설정창은 하나만 만들어 VN 씬에 두고 피하기가 호출 (씬마다
       따로 만들지 않음)
  3. 1스테이지(1번 챕터) : 스테이지 프로필(3-a) + 공격 패턴 3~4종 +
     그 챕터의 대본/캐릭터/배경
  - 순서는 1 → 2 → 3. 1·2 가 끝나기 전에 3 으로 넘어가지 않는다
    (3 이 막히면 1·2 만이라도 끝낸 상태로 마무리)

  완료 조건 :
  (1) VN 에서 설정창을 열고 닫을 수 있고, 항목 값이 실제로 적용됨
  (2) 설정창을 방향키/게임패드(+확인/취소)만으로 조작할 수 있음
      (마우스 필수 아님 — 콘솔 대응 방침)
  (3) 피하기 중 Esc/Start → 시간·장애물·전진이 멈춤 + 설정창 표시 →
      닫으면 같은 상태에서 이어짐. 설정창을 연 동안 시간이 줄지 않음
  (4) 설정창을 닫은 뒤 피하기 조작과 VN 조작이 모두 정상
  (5) 1스테이지를 VN → 피하기 → VN 로 한 판 플레이 가능

  범위 밖 : 타이틀 화면(7일차), 컵헤드식 실패 화면(나중에 구현할
  디테일), 세이브/로드 UI, 갤러리, 챕터 2 이후 양산(5~6일차 이후)

d. 요구한 기능을 만들기 위해서 어떤 식으로 생성하거나 변경해야 하는지
================================================================

  ■ 설정창 (VN 씬)
    - 항목 (기본안 — 확정 필요) : 마스터 볼륨 / BGM / 효과음 / 텍스트
      속도 / 오토 속도 / 닫기. 값은 슬라이더, 방향키 좌우로 증감
    - 열기/닫기 API : SettingsPanel.Open() / Close() / IsOpen (이름은
      가칭). VN 의 Menu 버튼과 피하기의 Pause 가 같은 API 를 호출
    - 조작 : 위/아래로 항목 이동, 좌/우로 값 변경, 확인/취소 =
      게임패드 buttonSouth/East + 키보드 Enter/Esc. 마우스도 동작은
      하되 필수는 아님
    - 값 저장 : 1차는 메모리 + PlayerPrefs 같은 간단한 저장으로 시작
      (ES3 세이브는 실사용 테스트 전이므로 이번엔 쓰지 않음, h절)

  ■ 피하기 일시정지 연동
    - AvoidInput 에 Pause 액션 추가 (Esc, 게임패드 Start)
    - AvoidPlayerController 가 Pause 를 받으면 GameController.Pause()
    - GameController.Pause() : IsGamePlay 를 유지한 채 Time.timeScale
      = 0, 설정창 열기. 닫힘 이벤트를 받으면 timeScale 복구
      · 시간/거리/장애물/바닥 스크롤이 전부 Time.deltaTime 기반이라
        timeScale 0 이면 같이 멈춤 (GameController.Update, 스크롤러,
        ApproachingObject 확인 필요 — 일부가 unscaled 면 수정)
    - 입력 전환 : 설정창이 열린 동안
      · 피하기 PlayerInput 의 Move/Jump/Forward 가 반응하지 않게 함
        (액션 맵 전환 또는 Pause 중 플래그로 무시)
      · 설정창이 쓰는 입력(UI 내비게이션)이 동작하게 함
      · 닫으면 위 둘을 원상복구
      ※ PlayerInputManager 를 껐다 켜는 방식은 피하기 중 VN 입력을
        끄는 용도이므로, 설정창 입력은 UI 입력(EventSystem 의
        InputSystemUIInputModule)을 쓰는 쪽으로 분리하는 것이 안전.
        구체 방식은 착수 후 PlayerInputManager/EventSystem 을 읽고 확정

  ■ 1스테이지 (3-a)
    - StageProfile(ScriptableObject) : 제한시간, 목표 거리, 패턴 목록
      (패턴 종류 + 발동 거리 + 개수/간격), 그 챕터 characterKey,
      배경 정보
    - 패턴 3~4종 (후보 — 확정 필요) : 낮은 장애물(점프) / 높은
      장애물(옆으로) / 감속 장애물 / 줄지어 오는 장애물 등. 기존
      AttackObject(멈춤/넉백/감속)를 재사용
    - 거리 기반 패턴 배치 : 나중에 컵헤드식 실패 화면(진행률 + 남은
      패턴 수)을 붙일 수 있도록 패턴을 "거리 → 패턴" 목록으로 둠.
      AvoidSession 에 도달 거리/지나간 패턴 수를 남길 자리 확보
    - startAvoid(스테이지명) 인자로 프로필을 선택 (3-c 에서 받기만
      하고 무시하던 인자를 사용)
    - 대본 : 1챕터 도입 파일 + 클리어 후 대화 파일 (3-c 의 구조)
    - 캐릭터/배경 리소스는 있는 것으로 임시 사용 가능. 그림이 없으면
      자리표시자로 두고 5~6일차에 채움

e. 다른 방법들 중에서 왜 d의 방식으로 만든 것인지
================================================================

  [ 설정창 : VN 씬에 하나 vs 씬마다 따로 ]
  - 하나 (채택) : 피하기가 Additive 라 VN 씬이 계속 로드돼 있음.
    따로 만들면 값/디자인이 어긋나고 일이 두 배

  [ 일시정지 : timeScale 0 vs 각 스크립트에 정지 플래그 ]
  - timeScale 0 (채택) : 시간/장애물/스크롤이 deltaTime 기반이라 한 줄로
    전부 멈춤. 단, unscaled 를 쓰는 곳(설정창 UI 연출 등)은 의도대로
    남겨 둠. 플래그 방식은 스크립트마다 추가해야 해서 빼먹기 쉬움

  [ 설정 저장 : ES3 vs PlayerPrefs ]
  - PlayerPrefs 계열(채택) : 설정 몇 개를 저장하는 데 충분. ES3 는
    세이브 데이터(챕터 진행도) 쪽으로 쓰고 실사용 테스트가 끝난 뒤
    통합 여부를 결정

  [ 1스테이지 패턴 : 코드에 하드코딩 vs 프로필 데이터 ]
  - 프로필(채택) : 챕터 8~10개를 양산해야 하므로 데이터로 빼야 함.
    컵헤드식 화면(진행률/남은 패턴 수)도 데이터에서 바로 계산 가능

h. 주의할 점 / 미정 사항
================================================================

  ■ 입력 전환이 가장 위험한 부분. 피하기 중 VN 입력은 컴포넌트를 껐다
    켜는 방식이라(키보드 페어링 문제로 바꾼 이력), 설정창 입력을 어느
    입력 체계로 받을지 잘못 잡으면 열고 닫은 뒤 키가 먹히지 않을 수
    있음. 설정창은 UI 내비게이션(EventSystem) 쪽 입력을 쓰는 방향으로
    착수 후 확정하고, 열고 닫기를 여러 번 반복해 확인

  ■ 3-c 검증 때 자동화 도구의 키 입력이 VN 복귀 뒤에 먹히지 않았음
    (VN 입력은 활성·페어링 상태). 사람이 직접 확인해야 하는 항목이므로
    5일차 시작 때 3-c 흐름을 직접 한 번 돌려 확인할 것

  ■ timeScale 0 중에도 코루틴의 WaitForSeconds 는 멈춤. 3-c 의 CLEAR/
    TIME OVER 지연(resultDelay) 도중에 일시정지를 막거나, 그 구간은
    Pause 입력을 무시할 것 (클리어 직후 일시정지로 꼬이는 것 방지)

  ■ Pause 로 멈춘 상태에서 시간 초과/클리어가 판정되지 않게 할 것
    (Update 가 멈추므로 자연스럽게 안 되지만, 설정창을 닫는 순간
    프레임에 큰 deltaTime 이 들어오는지 확인)

  ■ 설정창 값 저장 위치는 임시(PlayerPrefs 계열). 세이브 시스템(ES3)
    통합은 별도 결정 (로드맵 k절 "세이브 시스템 실사용 테스트 시점")

  ■ 설정창 항목, 패턴 종류/개수, 1챕터의 동화/캐릭터는 모두 미정 —
    f절 1번에서 사용자 확인 후 확정. 스토리(동화 선정 등)가 아직
    정해지지 않았으므로 1챕터는 임시 이름/자리표시자로 시작 가능

  ■ 이 계획의 UI 범위는 "VN 쪽 설정창 + 피하기 일시정지 연동". 피하기
    HUD 의 정식 디자인/타이틀/컵헤드식 실패 화면은 포함하지 않음

i. 진행 결과 (26.10.05)
