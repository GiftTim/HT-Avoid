d. 요구한 기능을 만들기 위해서 어떤 식으로 생성하거나 변경해야 하는지
================================================================

  ■ 핵심 구조 : "전진 속도" 하나를 모두가 따른다
    - GameController.StageSpeed (static) = 현재 전진 속도
      · 평소 moveSpeed(10), 멈춤 중 0, 넉백 중 음수
    - 바닥(GroundScroller), 장식(ScenerySpawner), 다가오는 오브젝트
      (ApproachingObject) 가 전부 이 값을 읽어 움직임
    - 그래서 피격 반응은 GameController 의 속도만 바꾸면 화면 전체가
      같이 멈추거나 뒤로 흐름

  ■ GameController.cs (개조)
    - timeLimit(90) / goalDistance(800) / moveSpeed(10)
    - RemainingTime, Distance, RemainingDistance, CurrentSpeed,
      HitCount, IsGamePlay
    - Stun(duration) : duration 동안 속도 0
    - Knockback(distance, duration) : duration 동안 속도
      -distance/duration → 진행 거리가 distance 만큼 줄어듦
    - 도착/시간 초과 : 지금은 멈추고 로그만 (3-c 에서 연결)

  ■ ApproachingObject.cs (신규)
    - 속도 = StageSpeed + ownSpeed 로 -Z 이동, despawnZ 뒤에서 삭제
    - 장식은 ownSpeed 0, 공격은 ownSpeed 만큼 더 빠름

  ■ ScenerySpawner.cs (신규) — 길 양옆 장식
    - spacing(6) 간격으로 좌우 ±sideX(6) 에 한 쌍씩 생성
    - prefab 이 비어 있으면 임시 기둥(Cube) 사용
    - 시작 시 길 전체에 미리 깔아둠

  ■ AttackObject.cs (신규) — 공격의 피격 데이터
    - reaction(Stun/Knockback), reactionTime, knockbackDistance
    - Apply(gameController) 로 반응 적용

  ■ PlayerHit.cs (신규) — 플레이어 피격 판정
    - OnTriggerEnter 에서 AttackObject 를 만나면 Apply
    - 반응 시간 + invincibleTime(1초) 동안 무적 + 깜빡임
    - Rigidbody(isKinematic) / BoxCollider(Trigger) 가 없으면 Awake
      에서 직접 붙임 (히트박스 중심/크기는 인스펙터 값)

  ■ AttackSpawner.cs (신규, 테스트용 패턴)
    - spawnCycle(1.2초)마다 좌우 랜덤 위치에 둘 중 하나 생성
      · 낮은 장애물(빨강, 2.5 x 0.5) : 맞으면 멈춤 0.8초
      · 높은 장애물(주황, 1.2 x 2.5) : 맞으면 0.5초에 걸쳐 15 뒤로
    - 정식 패턴/프로필(3-a, 3-d)이 생기면 교체

  ■ UIController.cs (개조)
    - 남은 시간(분:초.0), 남은 거리(m) 표시. 10초 이하면 빨간색
    - 텍스트를 지정하지 않으면 임시 HUD(오버레이 캔버스)를 직접 생성

  ■ 씬 (Avoid.unity — YAML 직접 수정)
    - Plane : GroundGrid.mat + GroundScroller
    - Scenery(신규 오브젝트) : ScenerySpawner
    - GameController 오브젝트 : GameController + UIController +
      AttackSpawner
    - Player : PlayerHit 추가, 2D 물리 3종 제거

e. 다른 방법들 중에서 왜 d의 방식으로 만든 것인지
================================================================

  [ 피격 반응 : 플레이어를 뒤로 움직임 vs 세계의 속도를 바꿈 ]
  - 세계의 속도 (채택) : 플레이어는 Z 고정이라는 좌표 규칙을 유지.
    "뒤로 튕김 = 진행 거리 감소" 가 숫자와 화면에 동시에 반영되고,
    바닥/기둥이 거꾸로 흐르는 것만으로 튕겨나는 느낌이 남

  [ 속도 공유 : 각 스크립트에 속도 필드 vs static StageSpeed ]
  - static (채택) : 런타임에 생성되는 오브젝트가 많아 참조를 일일이
    넘기기 번거롭고, 속도 값이 여러 곳에 흩어지면 바닥과 기둥이 따로
    노는 실수가 생김. 한 판에 GameController 는 하나뿐

  [ 임시 오브젝트 : 프리팹 vs 코드로 Cube 생성 ]
  - 코드 생성 (채택) : 그림이 아직 없고, 에디터 작업 없이 바로 확인할
    수 있음. 4일차(3-a)에 프리팹/프로필 방식으로 교체

  [ HUD : 기존 Canvas-Main 재사용 vs 코드로 임시 생성 ]
  - 임시 생성 (채택) : Canvas-Main 은 2D 시절 구성(카메라 공간,
    Scale 0)이라 그대로 못 씀. 정식 UI 는 디자인이 정해진 뒤 캔버스를
    만들고 UIController 의 두 텍스트 칸에 연결하면 임시 HUD 는 자동
    으로 안 만들어짐

f. 어떤 순서로 진행할 것인지
================================================================

  1. (완료) 코드 작성, 씬 YAML 연결
  2. (에디터) Unity 로 돌아가 씬 Reload → 컴파일 에러 확인
  3. (검증) Avoid.unity 단독 Play — b절 완료 조건 (1)~(6)
     · 26.10.03 에디터 MCP 로 부분 확인 : 컴파일 에러 없음, 방향키 위로
       전진(거리 증가), 남은 시간/거리 HUD 감소, 피격 횟수 증가,
       주황/빨강 장애물과 양옆 기둥 표시 확인
     · 미확인 : (3) 멈춤/넉백 구분, (4) 무적 중 재피격 없음, (5) 점프로
       빨강 넘기. 확인 중 에디터가 포커스를 잃어 프레임이 약 5fps 로
       떨어져 타이밍 측정이 불가능했음 → 직접 Play 해서 눈으로 확인 필요
  4. (검증) 800 을 다 달리면 콘솔에 "클리어", 90초가 지나면 "시간 초과"
  5. (튜닝) 속도/간격/히트박스/반응 수치
  6. 이상 없으면 Record 작성, 1일차·2일차 ChangePlan 을
     3. ChangeCompleted 로 이동 → 3일차(3-c) 착수

h. 주의할 점
================================================================

  ■ 씬을 에디터 밖에서 수정했으므로 Unity 로 돌아가면 Reload 를
    눌러야 함. 저장하지 않은 씬 변경은 사라짐. 수정 전 씬은 세션
    스크래치패드에 백업해 둠

  ■ 바닥 무늬가 멀어지는 쪽으로 흐르면 Plane 의 GroundScroller 에서
    Reverse 체크 (Plane 메쉬 UV 방향은 Play 로 확인 필요)

  ■ 히트박스 : PlayerHit 의 기본값(중심 y 0.44, 크기 0.5 x 1.8 x 0.5)은
    Body 스프라이트 위치에 맞춘 추정치. Scene 뷰에서 초록 박스를 보고
    조정. 판정이 너무 빡빡하면 크기를 줄이는 쪽이 피하기 게임에는 유리

  ■ 넉백 중에는 기둥/공격이 화면 안쪽으로 밀려나 바닥 끝(Z 45)을
    넘어갈 수 있음 — 임시 연출이라 그대로 둠

  ■ 임시 HUD 는 TMP 기본 폰트를 씀 (숫자/영문만 표시). 한글을 넣으려면
    한글 폰트 에셋 지정 필요

  ■ Shader.Find("Universal Render Pipeline/Unlit") : 빌드에서는
    셰이더가 포함돼 있어야 함. GroundGrid.mat 이 같은 셰이더를 쓰므로
    포함되지만, 임시 Cube 를 프리팹으로 바꾸면 이 코드는 사라짐

  ■ timeLimit 90 / goalDistance 800 / moveSpeed 10 이면 한 번도 안
    맞았을 때 80초에 도착 → 여유 10초. 수치는 전부 출발점
