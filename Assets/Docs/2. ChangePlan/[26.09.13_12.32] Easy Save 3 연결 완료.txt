1. 변경
================================================================

  참고 계획 문서의 c절(현재 상황 및 코드)과 실제 코드를 대조함.

  - VNGameSave.cs : Save()가 JsonUtility.ToJson + FileManager.Save를
    쓰고 있었고, ENCRYPT_FILES(false)가 미사용 상태인 것 확인 → 일치
  - FileManager.cs : Save/Load<T>가 평문 텍스트 입출력만 하는 것 확인
    → 일치 (변경 없음, 대화 대본 로딩용 메서드도 그대로)
  - TestGameSave.cs : FileManager.Load<VNGameSave>(...) 호출부 확인
    → 일치
  - Easy Save 3 임포트 상태(Assets/Plugins/Easy Save 3, 171개 스크립트,
    ES3Defaults.asset) 재확인 → 일치
  - ES3.cs / ES3Settings.cs 실제 API 시그니처 확인
    (ES3.Save<T>(key, value, filePath, settings),
     ES3.Load<T>(key, filePath, settings),
     new ES3Settings(EncryptionType, password)) → 계획한 코드와 일치
  - ES3FileStream이 저장 시 디렉터리를 자동 생성하는 것도 확인
    (기존 FileManager.TryCreateDirectoryFromPath와 동일한 역할을
    ES3가 대신 해줌)

  → 사소한 공백 줄 하나 외에는 계획 문서(c절)와 다른 점이 없어
    변경을 그대로 진행함 (1-b)

2. 기록
================================================================

  [ 변경 전 / 후 코드 ]

  ── VNGameSave.cs ──────────────────────────────────────────

  변경 전:
  ```csharp
  public const string FILE_TYPE = ".vns";
  public const string SCREENSHOT_FILE_TYPE = ".jpg";
  public const bool ENCRYPT_FILES = false;
  ...
  public void Save()
  {
      activeState = HistoryState.Capture();
      historyLog = HistoryManager.instance.history.ToArray();
      activeConversations = GetConversationData();
      variables = GetVariableData();

      string saveJSON = JsonUtility.ToJson(this);
      FileManager.Save(filePath, saveJSON);
  }
  ```

  변경 후:
  ```csharp
  public const string FILE_TYPE = ".vns";
  public const string SCREENSHOT_FILE_TYPE = ".jpg";
  public const bool ENCRYPT_FILES = true;
  private const string ENCRYPTION_PASSWORD = "HT-Avoid_SaveKey"; // TODO: 추후 빌드 시점 주입 등으로 교체 검토
  ...
  public void Save()
  {
      activeState = HistoryState.Capture();
      historyLog = HistoryManager.instance.history.ToArray();
      activeConversations = GetConversationData();
      variables = GetVariableData();

      ES3.Save<VNGameSave>("gameSave", this, filePath, GetSettings());
  }

  public static VNGameSave LoadFromDisk(string path)
  {
      return ES3.Load<VNGameSave>("gameSave", path, GetSettings());
  }

  private static ES3Settings GetSettings()
  {
      return ENCRYPT_FILES
          ? new ES3Settings(ES3.EncryptionType.AES, ENCRYPTION_PASSWORD)
          : new ES3Settings();
  }
  ```

  [ 변경 후 작동 흐름 ]

  1. TestGameSave에서 S 키 입력 → VNGameSave.activeFile.Save() 호출
  2. Save()가 HistoryState/대화 진행상황/VariableStore 값을 필드에
     채운 뒤, ES3.Save<VNGameSave>(...)를 호출
  3. ES3가 VNGameSave 객체 전체를 리플렉션으로 직렬화하고,
     GetSettings()가 반환한 AES 암호화 설정을 적용해
     filePath(Assets/appdata/Save Files/1.vns, 에디터 기준)에 씀
     (경로 폴더가 없으면 ES3FileStream이 자동 생성)
  4. TestGameSave에서 L 키 입력 → VNGameSave.LoadFromDisk(path) 호출
  5. ES3.Load<VNGameSave>(...)가 같은 암호화 설정으로 파일을 복호화해
     VNGameSave 객체를 복원 → activeFile에 대입
  6. 이어서 VNGameSave.Load()가 호출되어 복원된 필드 값을 바탕으로
     HistoryManager/VariableStore/ConversationManager 등 런타임
     상태를 실제로 되돌림 (이 부분은 기존과 동일, 변경 없음)

3. 저장 / 주의할 점
================================================================

  ■ ENCRYPTION_PASSWORD를 소스코드에 하드코딩함. 디컴파일 시 노출될
    수 있으나, 싱글플레이 프로젝트라 지금 단계에선 감수. 추후 빌드
    시점 주입 등으로 교체 검토 (코드에 TODO 주석으로 남겨둠)

  ■ 기존에 테스트로 저장된 평문 .vns 파일이 있었다면 새 암호화
    방식과 호환되지 않음 — 단, 확인 결과 Assets/appdata/Save Files/
    폴더가 비어있어 실제로는 영향 없음

  ■ FileManager.Save(string,string) / FileManager.Load<T>(string)
    제네릭 메서드는 이제 프로젝트 내 어디에서도 호출되지 않게 됨
    (세이브 관련 호출 두 곳을 모두 ES3로 교체했기 때문). 당장 삭제는
    하지 않았음 — 다른 용도로 재사용될 수도 있어 후속 판단으로 남김

  ■ VNGameSave에 필드를 추가할 때(2~5단계, 피하기/스킬/인벤토리
    진행되면서)는 반드시 [System.Serializable]을 유지해야 ES3가
    인식 가능함 (VNGameSave 클래스 자체엔 이미 붙어있음)

  ■ 실제 Unity 에디터에서의 Play 모드 왕복 테스트(S로 저장 → 파일이
    평문으로 안 보이는지 확인 → L로 로드해 정상 복원되는지 확인)는
    이 세션에서 직접 실행하지 못했음 — Unity 에디터를 열어 확인 필요
