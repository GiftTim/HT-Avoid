b. 요구한 기능
================================================================

  로드맵 i절 3-c. 목표는 "VN → 피하기 → VN" 1챕터가 처음부터 끝까지
  돌아가는 것.

  1. 도착(클리어) : 목적지에 도착하면 결과를 VN 변수로 넘기고 VN 으로 복귀
  2. 시간 초과 : 그 판만 즉시 처음부터 다시 시작 (재도전)
  3. VN 대본에서 [startAvoid] 한 줄이 "피하기를 클리어할 때까지" 기다림
     (클리어하면 다음 줄로 자연스럽게 이어짐)
  4. 선택지 오답 → 피하기 판 재플레이 → 클리어 후 그 대화를 처음부터
     다시 봄 (대본만으로 표현 가능해야 함)
  5. 피하기 결과(피격 횟수, 재도전 횟수, 남은 시간)를 VariableStore 에
     남겨 VN 의 LL_Condition 이 읽을 수 있게 함

  - 대상 : Avoid.unity, VN 씬(VisualNovel.unity), 신규 테스트 대본
  - 참고 계획 : 로드맵 g절 1번 / h절 / i절 3-c, ChangePlan
    [26.10.02_20.12] 3-b (속도 구조, GameController)

  완료 조건 :
  (1) 테스트 대본 실행 → 대사 → 피하기 → 클리어 → 다음 대사가 이어짐
  (2) 피하기에서 시간을 다 쓰면 "시간 초과" 표시 후 같은 판이 처음부터
      다시 시작됨 (VN 으로 나가지 않음)
  (3) 선택지에서 오답을 고르면 피하기가 다시 열리고, 클리어 후 클리어
      후 대화가 첫 줄부터 다시 나옴. 정답이면 다음으로 진행
  (4) 클리어 후 대사에서 $Avoid.hitCount 등을 조건문으로 읽을 수 있음
  (5) Avoid.unity 단독 Play 도 여전히 동작 (VN 없으면 로그만, 재도전은 동작)

  범위 밖 : 스테이지 프로필/보스 데이터(3-a, 5일차), 정식 클리어/패배 UI
  디자인, 세이브(챕터 진행도), 타이틀

d. 요구한 기능을 만들기 위해서 어떤 식으로 생성하거나 변경해야 하는지
================================================================

  ■ 핵심 구조 : "피하기가 끝날 때까지 startAvoid 가 기다린다"
    - startAvoid 코루틴이 씬을 로드한 뒤, AvoidSession.IsFinished 가
      true 가 될 때까지 yield 로 대기 → 끝나면 ReturnToVN() 호출
    - 그러면 대본은 [wait]startAvoid(...) 한 줄만 쓰면 되고, endAvoid
      줄이 필요 없어짐 (endAvoid 커맨드는 호환용으로만 남김)
    - 피하기 중 VN 입력을 끄는 기존 처리는 그대로 유지

  ■ AvoidSession.cs (신규, static, Assets/Scripts/Avoid/Core/)
    - 피하기 한 번의 결과를 VN 과 주고받는 창구. 씬이 언로드/재로드
      돼도 값이 유지돼야 하므로 static
    - Begin() : IsFinished=false, RetryCount=0 (VN 이 호출할 때만 초기화.
      시간 초과 재도전 때는 호출하지 않음)
    - NotifyRetry() : RetryCount++
    - Complete(hitCount, remainingTime) : 결과 저장, IsFinished=true
    - 결과를 VariableStore 로 쓰는 메서드 (WriteToVariables) :
      Avoid.hitCount / Avoid.retryCount / Avoid.remainingTime /
      Avoid.cleared(true) 를 없으면 만들고 값 설정

  ■ GameController.cs (개조)
    - GameClear() : 정지 → "CLEAR" 표시(짧게) → AvoidSession.Complete()
    - TimeOver() : 정지 → "TIME OVER" 표시(짧게) → 같은 판 재시작
    - 재시작 방식 : Avoid 씬을 언로드 후 다시 Additive 로드 (e절)
      · 씬 오브젝트가 죽는 동안에도 코루틴이 살아 있어야 하므로,
        VN 이 있으면 DialogueSystem.instance.StartCoroutine,
        없으면(단독 Play) SceneManager.LoadScene(Single) 로 처리
    - 연출용 대기 시간(CLEAR/TIME OVER 표시) 은 인스펙터 값 (기본 1.5초)

  ■ UIController.cs (소폭)
    - 상태 메시지 텍스트 하나 추가 : GameController 가 ShowMessage
      ("CLEAR!" / "TIME OVER") 호출. 임시 HUD 방식 유지
    - 기본 TMP 폰트는 한글이 안 나오므로 영문으로 표시 (h절)

  ■ CMD_DatabaseExtension_Avoid.cs (수정)
    - startAvoid(스테이지명 선택) : AvoidSession.Begin() → 로드 →
      IsFinished 대기 → AvoidSession.WriteToVariables() →
      ReturnToVN(). 스테이지명 인자는 3-a(5일차)에서 쓰므로 지금은
      받아만 두고 무시
    - 새 커맨드 restartDialogue() :
      · 부모(큐의 마지막) Conversation 의 진행을 0 으로 되돌리고
      · 맨 앞(선택지 결과) Conversation 이면 끝으로 보내 줄을 건너뜀
      · 실행 줄이 끝나면 엔진이 자연히 부모의 첫 줄부터 재생
    - Enemy.ResetClearState() 호출 제거

  ■ Enemy.cs (수정)
    - TakeDamage 안의 ReturnToVN 호출 삭제 (복귀 트리거 교체). Enemy
      파일/비활성 Fly 오브젝트는 3-0 정리 때 함께 처리

  ■ 테스트 대본 (신규) : Resources/Dialogue Files/Test/
    AvoidChapterTest.txt — 도입 → [wait]startAvoid() → 클리어 후 대화
    (조건문으로 $Avoid.hitCount 분기) → 선택지, 오답 줄에서
    [wait]startAvoid() 후 restartDialogue(). 클리어 후 대화를 한 파일로
    두어야 "그 파일의 처음부터" 가 성립함 (구성은 f절 6번)
    대본 예 (문법은 기존 선택지/조건문 테스트 파일에 맞춤) :

      choice "이 동화의 주인공은?"
      {
          -정답 선택지
              narrator "맞아요!"
          -오답 선택지
              narrator "틀렸어요... 다시 도전해요"
              [wait]startAvoid()
              [wait]restartDialogue()
      }

  ■ 대본에 진입시키는 방법 : 기존 테스트 진입점(씬의 테스트 스크립트)
    확인 후 AvoidChapterTest 를 불러오도록 한 줄 수정 (VisualNovel
    씬의 Test 오브젝트, f절 5번에서 확인)

e. 다른 방법들 중에서 왜 d의 방식으로 만든 것인지
================================================================

  [ 복귀 : 게임이 VN 을 직접 호출 vs startAvoid 가 기다림 ]
  - 대기 방식 (채택) : 기존엔 Enemy 가 DialogueSystem 을 찾아 복귀를
    밀어넣었고, 대본의 endAvoid 줄은 이미 언로드된 씬을 또 언로드하는
    구조라 불안했음. startAvoid 가 "끝날 때까지 기다림" 하나로 대본이
    선형(위에서 아래로)이 되어 작가가 쓰기 쉽고, 오답 재진입도 같은
    줄을 한 번 더 쓰면 끝남
  - 대신 게임 쪽은 VN 을 전혀 몰라도 됨 (AvoidSession 에 결과만 남김)
    → Avoid.unity 단독 Play 가 자연스럽게 동작

  [ 재시작 : 씬 안에서 되감기 vs 씬 다시 로드 ]
  - 씬 다시 로드 (채택) : 공격/장식 오브젝트, 가속, 무적, 파티클 등
    상태가 많아 되감기는 빼먹는 것이 생기기 쉬움. 로드 한 번이면
    확실히 초기 상태. 대신 순간 깜빡임이 있을 수 있어 "TIME OVER"
    표시 직후에 해서 눈에 안 띄게 함
  - 되감기는 Fall/Aura/스폰 정리를 전부 짜야 해서 일주일 일정에 비쌈

  [ 결과 전달 : static 클래스 vs VN 변수에 바로 쓰기 ]
  - AvoidSession(static) 경유 (채택) : 시간 초과 재도전 중에는 씬이
    계속 새로 로드되므로 RetryCount 같은 값이 씬 밖에 있어야 함.
    VariableStore 에는 클리어 순간에만 한 번 씀

  [ 오답 재진입 : 새 로직줄 만들기 vs 커맨드 + 기존 선택지 ]
  - 커맨드 (채택) : LL_Choice 를 고치면 엔진 전체에 영향. 결과 줄에
    커맨드를 쓰는 방식은 기존 엔진 기능(선택지 + [wait] 커맨드)만으로
    표현되고, 로드맵 3-c 에서 "엔진 쪽 확인 필요" 였던 부분이 해소됨
  - 한계 : "처음부터" 의 기준은 "그 Conversation(= 그 대본 파일)의
    처음". 그래서 클리어 후 대화는 별도 파일로 둬야 함. 한 파일에
    도입부 + 피하기 + 클리어 후 대화가 다 있으면 도입부부터 다시 보게
    됨 (f절 6번에서 파일 분리 규칙 확정)

  [ 클리어 후 화면 : 정식 UI vs 임시 텍스트 ]
  - 임시 텍스트 (채택) : 디자인 미정. 정식 UI 는 5~6일차 이후

h. 주의할 점
================================================================

  ■ 재시작 때 VN 입력/대사창 상태 : 재시작 중에는 ReturnToVN 이 불리지
    않으므로 대사창은 계속 숨김, VN 입력은 계속 꺼진 상태여야 함.
    Additive 로드 후 Avoid 카메라/HUD 가 다시 VN 위에 덮이는지
    (카메라 Depth, 26.09.14 ChangePlan) 확인

  ■ 단독 Play(VN 없음) : DialogueSystem.instance == null 이므로 코루틴
    주체와 재시작 방식을 분기해야 함 (d절 GameController)
