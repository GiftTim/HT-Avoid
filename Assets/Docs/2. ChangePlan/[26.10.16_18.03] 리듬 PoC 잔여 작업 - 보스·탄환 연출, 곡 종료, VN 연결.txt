[0. 점검 결과 - 로드맵 e절과 실제 코드가 다르다]

  로드맵(26.10.15 23:07) e절은 "리듬 코어 전부 미구현"이라 적혀 있으나,
  Assets/Scripts/Rythm/ 에는 이미 아래가 구현돼 있다 (커밋 7c3508b 까지).

  | h절 순서 | 내용                     | 코드                         | 상태 |
  |----------|--------------------------|------------------------------|------|
  | ①        | Rythm.unity 정리         | (씬)                         | 완료 (Collider 없음, 타일 원점 근처) |
  | ②        | 음악 시계                | RhythmConductor              | 완료 (dspTime + PlayScheduled, latencyOffset) |
  | ③        | 자동 달리기 + 카메라     | RhythmPlayerMotion / RhythmCameraFollow | 완료 |
  | ④        | 점프 곡선                | RhythmPlayerMotion           | 완료 (박 단위 포물선) |
  | ⑤        | 채보 / 탄환              | ChartData / RhythmNoteView   | 데이터는 완료, 그림은 임시 원 |
  | ⑥        | 판정 + HP                | NoteManager / RhythmBattle   | 완료 (HP 0 → OnFailed) |
  | ⑦        | 반격 + 점수 + 피버       | NoteManager / RhythmScore    | 코드 완료, 씬에 미배치 (아래) |
  | ⑧        | 보스 종료 모션 + 클리어  | RhythmBattle.OnCleared       | 이벤트만 있음. 보스가 없음 |
  | ⑨        | VN 연결                  | (없음)                       | 미구현 |

  발견한 빈틈
  - RhythmScore 는 코드가 있으나 Rythm.unity 에 붙어 있지 않다 (GUID 0건).
    RhythmDebugRunner 의 score 칸이 비어 있을 가능성이 높다
  - 실패(OnFailed) 후 재시작하는 코드가 없다 (로그만 찍고 멈춤)
  - HP/점수/피버 UI 가 없다 (Console 로그로만 확인 중)
  - 보스가 없고, 탄환은 RhythmNoteView 의 임시 원이다
  - startAvoid 가 "Avoid" 씬 이름, AvoidSession(hitCount/remainingTime)에
    묶여 있어 리듬 씬을 못 연다
  - 일시정지(Esc, timeScale 0) 시 dspTime 은 계속 흐른다 -> 곡이 어긋남

[1. 목표]

  "VN -> 리듬 한 판(보스가 탄환을 던짐) -> VN" 이 한 번 도는 PoC 완성.
  실패 시 곡 처음부터 즉시 재도전, 클리어 시 결과가 VN 변수로 넘어간다.

[2. 작업 순서 (각 단계는 따로 확인하고 넘어간다)]

  단계 A. 씬 연결 확인 (코드 변경 거의 없음)
    - Rythm.unity 에 RhythmScore 를 붙이고 RhythmDebugRunner.score 에 연결
    - 임시 채보(ChartData)로 Play 해서 Console 로그 확인
      · 박 로그와 소리가 맞는지 (latencyOffset 체감 확인)
      · 회피/반격/Dodged/Miss 판정, HP 감소, 피버 발동, 클리어 로그
    - 확인 항목을 막히는 순서대로 기록해 둔다

  단계 B. 실패 -> 재시작 (RhythmBattle / 새 RhythmStageController)
    - OnFailed 를 받으면 짧은 연출 후 NoteManager.Load -> Battle.Begin ->
      Conductor.Play 를 다시 호출 (곡 처음부터, 씬 재로드 안 함)
    - RhythmNoteView 는 재시작 시 기존 뷰를 지우고 다시 만들도록 수정
      (지금은 Start 에서 한 번만 만든다)
    - RhythmScore.Begin() 도 같이 호출해 점수/피버 초기화
    - 재시작 횟수 retryCount 를 센다 (VN 변수용)

  단계 C. 최소 UI (uGUI, Canvas 는 UI 전용)
    - HP 바(300 기준), 점수, 콤보, 피버 게이지, 판정 문구(PERFECT/GREAT/
      PASS/MISS), 정확도는 결과 화면에서만
    - 이벤트 구독만 한다 (Battle.OnPlayerHpChanged, Score 이벤트,
      NoteManager.OnJudged). 계산은 기존 클래스가 이미 한다

  단계 D. 보스 + 던지기 연출 (RhythmBoss 신규)
    - 화면 오른쪽 고정 (f절 권장). 카메라 자식 또는 매 프레임 카메라 x 기준
    - 상태기계 : Idle / Throw / Hit / Cry(또는 Flee). HP 없음
    - 탄환 비행 : "던진 시각(노트 시각 - flightBeats) -> 노트 시각" 보간.
      도착 위치 = RhythmPlayerMotion.TimeToWorldX(노트 시각) (이미 있는 식)
      -> RhythmNoteView 가 하던 위치 계산을 "보스 손 위치에서 출발" 로 확장
    - 반격 성공(Perfect/Great) 시 Hit 모션, 곡 끝에서 Cry/Flee
    - 보스/탄환 그림은 임시 스프라이트로 시작, 나중에 교체

  단계 E. 곡 종료 처리
    - 마지막 노트 판정 후(또는 곡 길이 끝) 보스 종료 모션 -> 잠시 대기 ->
      클리어 확정. 지금 RhythmBattle 은 "마지막 노트 판정 = 즉시 Stop"
      이라 곡 꼬리가 잘린다. 클리어 확정을 모션 뒤로 미룬다
    - 종료 모션이 끝나면 결과 기록 (단계 F)

  단계 F. VN 연결
    - 새 세션 클래스 RhythmSession(static) : AvoidSession 구조를 그대로
      가져오되 필드를 리듬용으로 (cleared, retryCount, missCount,
      accuracy, rank, maxCombo). 값은 이후 $Rhythm.* 변수로 기록
    - 새 커맨드 startRhythm(채보 이름) : Rythm 씬을 Additive 로 얹고
      RhythmSession.IsFinished 를 기다린 뒤 변수 기록 -> 씬 언로드 ->
      VN 복귀. CMD_DatabaseExtension_Avoid 의 StartAvoid / ReturnToVN 을
      재사용 (씬 이름과 세션만 다르다)
    - 채보 로드 : Resources/Charts/ 에서 이름으로 찾기 (StageProfile 이
      Resources/Stages/ 를 쓰는 방식과 동일)
    - restartDialogue 는 그대로 재사용 (오답 -> 리듬 재진입)
    - 씬 얹기 규칙은 g절 그대로 : 카메라 Depth 를 VN 보다 높게
    - 입력 충돌 : startAvoid 와 같이 PlayerInputManager.SetInputEnabled
      (false) 로 VN 입력을 끈다. NoteManager 는 Keyboard.current 를 직접
      읽으므로 영향 없음
    - 테스트 대본 1개 (Resources/Dialogue Files/Test/) : 도입 -> startRhythm
      -> 클리어 후 대화(결과에 따라 대사 변화)

  단계 G. 일시정지 (PoC 이후로 미뤄도 됨)
    - 설정창(Esc) 이 열리면 Conductor 가 AudioSource.Pause + 정지 시각
      기록, 닫히면 정지한 길이만큼 songStartDsp 를 뒤로 민다
    - 지금은 timeScale 0 이어도 dspTime 이 흘러 판정이 어긋나므로, PoC
      에서는 "리듬 중 Esc 비활성"이 가장 간단하다

[3. 결정이 필요한 것 (작업 중 모르면 이 기본값으로 진행)]

  1. 재시작 방식 : 씬 재로드 X, 같은 씬 안에서 상태 초기화 (기본값)
  2. 종료 모션 길이 : 2초 고정 (기본값. 챕터별 차이는 PoC 이후)
  3. 결과 변수 키 : $Rhythm.cleared / retryCount / missCount / accuracy /
     rank (기본값. AvoidSession 의 hitCount 계열은 건드리지 않음)
  4. 커맨드 이름 : startRhythm 신설. startAvoid 는 3D 코드 정리 전까지
     그대로 둔다 (이름 변경은 j절 미정 사항)
  5. 패드 버튼 : A / X 로 이미 반영됨 (NoteManager)

[4. 하지 않는 것]
  - 3D 피하기 코드 삭제 (j절 미정, 이번에 지우지 않음)
  - 체크포인트 / 공중 점프 / 길게 누르기 / 지연 보정 화면
  - 실제 곡, 실제 보스 그림, 챕터별 채보
  - 연타 노트 (로드맵 c절에 규칙만 있고 NoteType 에 아직 없음)

[5. 검증 방법]

  - 단계 F 는 VisualNovel.unity 에서 테스트 대본으로 왕복 1회
    (클리어 경로 + 실패 후 재도전 경로 + 선택지 오답 재진입 경로)
  - 판정 정확도는 사람이 박에 맞춰 눌러 보는 수밖에 없다 (자동 테스트
