b. 요구한 기능
================================================================

  26.10.07 Record 의 "지금 고민 중 (먼저 진행)" 2건을 하나로 묶음.

  1. 마우스 클릭을 전부 없애고 키보드 + 콘솔(게임패드)로만 진행
  2. 선택지를 키보드 + 게임패드로만 조작

  완료 조건 :
  (1) 게임 화면에서 마우스 커서가 보이지 않고, 마우스로 가리키기/클릭/
      휠을 해도 UI 가 반응하지 않음
  (2) 선택지가 뜨면 첫 항목이 선택된 상태로 시작하고, ↑/↓(패드 십자키·
      스틱)로 이동, Space/Enter(패드 A)로 확정됨
  (3) 지금 선택 중인 항목이 눈으로 구분됨
  (4) 선택지를 Space/Enter 로 확정해도 다음 대사가 빨리 넘어가지 않음
  (5) 설정창을 선택지 도중에 열었다 닫아도 선택지 조작이 이어짐

  범위 밖 (별도 진행) :
  - 선택지 그림 교체(저작권) — 스프라이트만 바꾸면 되고 코드 수정 없음
  - 설정창을 씬에 배치/복구, HUD 수정 — 무엇을 고칠지 사용자 확인 후
  - 로그(히스토리) 창을 키보드/패드로 스크롤 (h절 참고)
  - 이름 입력창(InputPanel)의 게임패드 문자 입력

    키보드로 고를 수 없음. 버튼 내비게이션은 Automatic, 선택 색과 평소

    않음 (guid 검색으로 확인). AvoidInput 에도 Attack 액션이 이미 없음

  [ 이미 키보드로 되는 곳 ]
  - VN 진행 : Space/Enter = Next, ←/→ = 히스토리, ' = 로그
  - 설정창 : Esc/Start 로 열고 닫기, ↑/↓ 항목 이동, ←/→ 값 변경.
    닫기 버튼도 선택 후 Space/Enter 로 눌림
  - 이름 입력창 : Enter 로 제출 (TMP_InputField.onSubmit)

  [ 같이 고쳐야 하는 기존 문제 ]
  - ConversationManager.onUserPrompt_Next 는 선택지/입력창을 기다리는
    중에도 userPrompt 를 true 로 만든다. 로직 줄(choice, input 등)은 이
    값을 소비하지 않으므로, 그대로 남아 있다가 다음 대사에서 소비되어
    타이핑이 곧바로 빨라진다(hurryUp).
    지금까지는 선택지를 마우스로 눌러서 드러나지 않았지만, Space/Enter
    로 확정하게 되면 매번 발생한다 (Space/Enter 가 Next 에도 묶여 있음)

d. 요구한 기능을 만들기 위해서 어떤 식으로 생성하거나 변경해야 하는지
================================================================

  ■ 마우스 제거 (씬 수정 없이 코드로)
    - PlayerInputManager.Start() 에서 한 번 실행
      · Cursor.visible = false (빌드에서는 Cursor.lockState = Locked 까지)
      · InputSystemUIInputModule 의 point / leftClick / middleClick /
        rightClick / scrollWheel 을 null 로 → UI 가 마우스에 반응하지 않음.
        move / submit / cancel 은 그대로 두어 키보드·패드 내비게이션 유지
    - AimCursor.cs / PlayerAttack.cs (+ .meta) 삭제

  ■ 선택지 키보드/패드 조작 (ChoicePanel)
    - 선택지 생성이 끝나면 보이는 버튼끼리 위/아래 내비게이션을 직접
      지정(Explicit, 끝에서 반대쪽 끝으로 순환)하고 첫 버튼을
      EventSystem.SetSelectedGameObject 로 선택
    - 버튼 생성 시 선택 색(selectedColor)을 설정창과 같은 노란색으로 지정
    - 선택이 풀리면(설정창을 닫은 직후 등) 마지막으로 선택돼 있던 버튼을
      다시 선택
    - 숨길 때 선택 해제
    - 확정은 버튼의 기존 onClick 을 그대로 사용 (EventSystem 의 Submit 이
      선택된 버튼의 onClick 을 호출)

  ■ Next 입력이 선택지 뒤 대사로 새지 않게 (ConversationManager)
    - onUserPrompt_Next 에서 로직 줄 실행 중(isOnLogicalLine)이면 무시

e. 다른 방법들 중에서 왜 d의 방식으로 만든 것인지
================================================================

  - EventSystem 을 씬에서 직접 고치는 방법(인스펙터에서 Point/Click 을
    None 으로) : 결과는 같지만 씬 파일을 고쳐야 하고, 누가 다시 기본값
    으로 되돌리면 마우스가 조용히 살아난다. 코드로 두면 "마우스 미사용"
    이 한 곳에 적혀 있어 찾기 쉽다. 나중에 PC 판에서 마우스를 다시
    지원하고 싶으면 그 함수만 끄면 된다
  - 마우스 장치를 통째로 끄는 방법(InputSystem.DisableDevice) : 에디터
    에서도 마우스가 죽어 작업이 불편하고, 되돌리는 처리가 필요해 과하다
  - 선택지를 EventSystem 없이 직접 만드는 방법(인덱스를 들고 ↑/↓ 를 직접
    읽기) : 설정창이 이미 EventSystem 내비게이션으로 만들어져 있어 같은
    방식을 쓰는 것이 일관되고, 게임패드 대응(십자키/스틱/A 버튼)이
    따로 코드를 쓰지 않아도 된다
  - 선택 표시를 화살표 그림으로 하는 방법 : 선택지 그림을 어차피 교체할
    예정이라, 지금은 그림과 무관한 색 변화만 넣는다. 새 그림이 정해지면
    그때 화살표/테두리 등을 붙인다
  - Next 누수는 ChoicePanel 에서 allowUserPrompts 를 껐다 켜는 방법도
    있지만, 히스토리 보기(OnStart/StopViewingHistory)가 같은 값을
    쓰고 있어 서로 덮어쓴다. isOnLogicalLine 으로 막으면 겹치지 않고
    이름 입력창의 같은 문제도 함께 해결된다

h. 주의할 점 / 미정 사항
================================================================

  - 로그(히스토리) 창은 ScrollRect 라서 마우스 휠을 끄면 스크롤할 방법이
    없어진다. 키보드/패드 스크롤은 별도 작업으로 필요
  - 이름 입력창의 확인 버튼은 마우스로 못 누르게 되지만 Enter 제출이
    있어 키보드로는 문제 없음. 게임패드로는 글자 입력 자체가 안 되므로
    콘솔 대응 시 이름 입력을 뺄지/가상 키보드를 쓸지 정해야 함
  - 에디터에서는 커서를 잠그지 않는다(Cursor.visible 만 끔). 잠그면
    Play 중 인스펙터를 만지려 할 때마다 Esc 를 눌러야 하고, Esc 는
    설정창 열기와 겹친다
  - Test/ 폴더 스크립트(Testing*.cs 등)는 구 Input.GetKey 를 쓰는
    디버그용 — 이번에는 손대지 않음
  - 선택 색(노란색)은 임시. 선택지 그림 교체 때 다시 정한다

  [ 미정 — 사용자 확인 필요 ]
  - 선택지 그림 스타일 : 단색 UI / 직접 제작 / 에셋 구매
    (26.10.08 커밋에 참고 이미지 4종이 추가됨 — 동화풍 / 레드 사이버)
  - "설정창이 씬에 없다" 의 뜻 : 컴포넌트는 VisualNovel 씬에 있음.
    코드가 만드는 임시 UI 대신 씬에 직접 배치한 UI 를 원한다는 뜻인지
  - 어떤 HUD 의 무엇을 고칠지 (피하기의 시간/거리 임시 HUD 인지)
