1. 변경
================================================================

  참고 계획 문서의 c절(현재 상황 및 코드)과 실제 Assets/Scenes/
  Avoid.unity 상태를 대조함.

  - PlayerAttack.cs / IDamageable.cs / AvoidInput.inputactions / Enemy
    레이어(TagManager.asset) / Player의 Transform(위치, 스케일 0.5) →
    전부 c절 기록과 일치

  - Enemy1 / Enemy2 / Enemy3 → 불일치. c절은 "아직 없음"으로 되어
    있었으나, 실제로는 이미 씬에 배치되어 있었음 (SpriteRenderer만
    있고 Layer=Default, Collider2D/Enemy.cs 없음)
  - Player 오브젝트 구조 → 불일치. Player 본체의 SpriteRenderer가
    삭제되고, 대신 자식 오브젝트 "Body"(주황 사각형)와 "Square"(흰
    막대, 계획한 AttackEffect와 형태 유사)가 추가되어 있었음

  → 계획서에 i절(실행 전 확인 결과)로 차이점을 기록하고 변경을
    중지한 뒤, 사용자에게 3가지를 확인함 :
    1. Enemy1/2/3 → 기존 오브젝트 재사용 (Layer 변경 + 컴포넌트만 추가)
    2. "Square" → 이름을 AttackEffect로 바꿔 재활용
    3. "Body" → 이번 범위 밖, 그대로 둠 (사용자 확인 : 나중에 캐릭터를
       넣을 자리로 미리 만들어 둔 것, 레이어가 필요할 수도 있어 미리
       준비해 둔 자식 오브젝트)

  → 위 확인을 마치고 계획한 대로 변경 진행 (1-a로 중지했다가, 사용자
    답변을 반영해 재개)

  ```csharp
  public class Enemy : MonoBehaviour, IDamageable
  {
      public void TakeDamage(int amount)
      {
          Debug.Log($"{name} 공격당함 (피해량: {amount})");
          Destroy(gameObject);
      }
  }
  ```

  ── PlayerAttack.cs ────────────────────────────────────────

  변경 전:
  ```csharp
  using UnityEngine;
  using UnityEngine.InputSystem;

  [RequireComponent(typeof(PlayerInput))]
  public class PlayerAttack : MonoBehaviour
  {
      [Header("Attack")]
      [SerializeField] private int damage = 10;
      [SerializeField] private float attackDistance = 1.2f;
      [SerializeField] private float attackRadius = 0.6f;
      [SerializeField] private float attackCooldown = 0.4f;
      [SerializeField] private LayerMask enemyLayer;

      private PlayerInput input;
      private InputAction attackAction;
      private Camera mainCamera;
      private float lastAttackTime = float.NegativeInfinity;

      ...

      private void OnAttackStarted(InputAction.CallbackContext context)
      {
          if ( Time.time - lastAttackTime < attackCooldown )
              return;

          if ( TryGetAimWorldPoint(out Vector2 aimPoint) == false )
              return;

          lastAttackTime = Time.time;

          Vector2 origin      = transform.position;
          Vector2 toAim       = aimPoint - origin;
          Vector2 direction   = toAim.sqrMagnitude > 0.0001f ? toAim.normalized : Vector2.right;
          Vector2 hitCenter   = origin + direction * attackDistance;

          Collider2D[] hits = Physics2D.OverlapCircleAll(hitCenter, attackRadius, enemyLayer);
          foreach ( Collider2D hit in hits )
          {
              IDamageable damageable = hit.GetComponentInParent<IDamageable>();
              damageable?.TakeDamage(damage);
          }
      }

      // TryGetAimWorldPoint(...) 는 변경 없음
  }
  ```

  변경 후 (판정 로직 자체는 그대로, 이펙트 표시 로직만 추가) :
  ```csharp
  using System.Collections;
  using UnityEngine;
  using UnityEngine.InputSystem;

  [RequireComponent(typeof(PlayerInput))]
  public class PlayerAttack : MonoBehaviour
  {
      [Header("Attack")]
      [SerializeField] private int damage = 10;
      [SerializeField] private float attackDistance = 1.2f;
      [SerializeField] private float attackRadius = 0.6f;
      [SerializeField] private float attackCooldown = 0.4f;
      [SerializeField] private LayerMask enemyLayer;

      [Header("Attack Effect")]
      [SerializeField] private Transform attackEffectTransform;   // 신규
      [SerializeField] private SpriteRenderer attackEffectRenderer; // 신규
      [SerializeField] private float effectDuration = 1f;          // 신규, 인스펙터 조절용

      private PlayerInput input;
      private InputAction attackAction;
      private Camera mainCamera;
      private float lastAttackTime = float.NegativeInfinity;
      private Coroutine hideEffectCoroutine; // 신규

      ...

      private void OnAttackStarted(InputAction.CallbackContext context)
      {
          if ( Time.time - lastAttackTime < attackCooldown )
              return;

          if ( TryGetAimWorldPoint(out Vector2 aimPoint) == false )
              return;

          lastAttackTime = Time.time;

          Vector2 origin      = transform.position;
          Vector2 toAim       = aimPoint - origin;
          Vector2 direction   = toAim.sqrMagnitude > 0.0001f ? toAim.normalized : Vector2.right;
          Vector2 hitCenter   = origin + direction * attackDistance;

          Collider2D[] hits = Physics2D.OverlapCircleAll(hitCenter, attackRadius, enemyLayer);
          foreach ( Collider2D hit in hits )
          {
              IDamageable damageable = hit.GetComponentInParent<IDamageable>();
              damageable?.TakeDamage(damage);
          }

          ShowAttackEffect(direction); // 신규 호출
      }

      // 신규 메서드
      private void ShowAttackEffect(Vector2 direction)
      {
          if ( attackEffectTransform == null || attackEffectRenderer == null )
              return;

          float angle       = Mathf.Atan2(direction.y, direction.x) * Mathf.Rad2Deg;
          float parentScaleX = transform.lossyScale.x; // Player 스케일(0.5) 보정용

          attackEffectTransform.localRotation = Quaternion.Euler(0, 0, angle);
          attackEffectTransform.localPosition = (Vector3)direction * (attackDistance * 0.5f / parentScaleX);

          Vector3 scale = attackEffectTransform.localScale;
          scale.x = attackDistance / parentScaleX;
          attackEffectTransform.localScale = scale;

          attackEffectRenderer.enabled = true;

          if ( hideEffectCoroutine != null )
              StopCoroutine(hideEffectCoroutine);
          hideEffectCoroutine = StartCoroutine(HideEffectAfterDelay());
      }

      // 신규 메서드
      private IEnumerator HideEffectAfterDelay()
      {
          yield return new WaitForSeconds(effectDuration);
          attackEffectRenderer.enabled = false;
          hideEffectCoroutine = null;
      }

      // TryGetAimWorldPoint(...) 는 변경 없음
  }
  ```

  ── Assets/Scenes/Avoid.unity (하이어라키/인스펙터 값 변경) ──

  변경 전 → 변경 후 :
  - Enemy1 / Enemy2 / Enemy3
    · Layer : Default(0) → Enemy(9)
    · 컴포넌트 : SpriteRenderer만 → SpriteRenderer + CircleCollider2D
      (Radius 0.5, Is Trigger 체크) + Enemy.cs 추가
  - Player 자식 "Square" → "AttackEffect"로 이름 변경
    · SpriteRenderer.Enabled : 1(항상 켜짐) → 0(시작 시 꺼짐, 공격 시에만
      코드가 켬)
  - Player 의 PlayerAttack 컴포넌트
    · attackEffectTransform → AttackEffect(위 오브젝트) 연결
    · attackEffectRenderer → AttackEffect의 SpriteRenderer 연결
    · effectDuration → 1 (기본값, 인스펙터에서 조절 가능)
  - "Body" 오브젝트 : 변경 없음 (범위 밖)


  [ 변경 후 작동 흐름 ]

  1. 플레이어가 마우스 좌클릭 (AvoidInput의 "Attack" 액션 발동)
  2. PlayerAttack.OnAttackStarted 실행
     a. 쿨다운(0.4초) 체크 → 통과 못 하면 여기서 끝
     b. 마우스 스크린 좌표를 Player와 같은 z 평면(z=0) 월드 좌표로 변환
        (aimPoint)
     c. direction = (aimPoint - Player위치) 정규화
     d. hitCenter = Player위치 + direction * 1.2(attackDistance)에 반지름
        0.6(attackRadius) 원형 판정 생성 → Enemy 레이어에 걸리고
        IDamageable을 구현한 대상(Enemy1/2/3)이 있으면 TakeDamage(10) 호출
        → Enemy.TakeDamage가 콘솔에 로그를 남기고 Destroy(gameObject)로
        스스로를 제거 (요구사항 1)
     e. ShowAttackEffect(direction) 호출
  3. ShowAttackEffect :
     a. direction으로 각도 계산 → AttackEffect의 로컬 회전에 적용
        (요구사항 4 — 클릭 방향과 Player 중심을 잇는 방향)
     b. AttackEffect 로컬 위치를 "Player중심~사거리(1.2) 끝의 중점"으로,
        로컬 스케일.x를 사거리(1.2, Player 스케일 0.5 보정 후 2.4)로 설정
        → 결과적으로 Player 중심에서 시작해 사거리 끝까지 뻗는 막대 모양
        (요구사항 3)
     c. AttackEffect의 SpriteRenderer를 켬 (요구사항 2 전반부)
     d. 이전에 실행 중이던 숨김 코루틴이 있으면 취소하고 새로 시작
  4. HideEffectAfterDelay 코루틴이 effectDuration(기본 1초, 인스펙터
     조절 가능) 뒤 SpriteRenderer를 꺼서 AttackEffect가 사라짐
     (요구사항 2 후반부)

3. 저장 / 주의할 점
================================================================

  ■ 이 문서를 Assets/Docs/3. ChangeCompleted/[26.09.15_14.44] 기본
    공격 기능 보강 완료 (피격 테스트, 공격 이펙트).txt 로 저장함

  ■ Unity 에디터 Play 모드에서의 실제 확인(클릭 시 AttackEffect가
    Player 중심~사거리만큼 뻗어 나오는지, Enemy1/2/3를 맞히면 콘솔
    로그와 함께 사라지는지, effectDuration 값을 인스펙터에서 바꿨을 때
    실제로 지속시간이 바뀌는지)은 이번 세션에서 직접 실행하지 못했음
    — 에디터를 열어 확인 필요

  ■ Player의 localScale(0.5)이 바뀌면 ShowAttackEffect의 parentScaleX
    보정값도 자동으로 같이 바뀌므로 별도 코드 수정은 필요 없음. 단,
    Player의 Scale이 X/Y가 서로 다른 비균일(non-uniform) 값으로
    바뀌는 경우는 지금 코드(X축 기준으로만 보정)로는 정확하지 않게
    되므로, 그런 변경이 생기면 이 부분을 다시 확인해야 함

  ■ CircleCollider2D의 Radius(0.5)는 Enemy 스프라이트(기본 Square,
    1x1 크기 가정) 기준의 대략값이며, 실제 아트가 들어오면 크기에
    맞게 다시 조정해야 함

  ■ AttackEffect(막대 모양)와 실제 판정 범위(hitCenter 기준 원형)는
    시각적으로 정확히 일치하지 않음 — 계획서(2. ChangePlan) h절에
    이미 명시된 대로, 이번 범위에서는 "판정이 대략 어디까지 닿는지"를
    보여주는 용도로만 사용

  ■ Enemy1/2/3의 Enemy.cs는 맞으면 즉시 Destroy하는 테스트 전용
    구현이며, 실제 보스 시스템(HP 차감 등)은 로드맵 5단계에서 별도
    설계 예정 (계획서 h절과 동일) — Enemy.cs를 보스 스크립트의 기반
    으로 재사용하지 말 것

  ■ "Body" 오브젝트는 이번 작업에서 건드리지 않음 — 추후 실제 캐릭터
    스프라이트/레이어 작업 시 별도로 다룰 예정 (사용자 확인 사항)
