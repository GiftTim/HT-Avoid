b. 문제점
================================================================

  VN 의 [wait]startAvoid(Stage1) 로 들어가 피하기를 클리어하면
  화면에 CLEAR 가 뜬 채로 멈추고 VN 으로 돌아가지 않는다.
  (같은 증상이 아래 "변수 Avoid.hitCount 를 찾을 수 없음" 오류와
   함께 나타난다 — 두 문제는 같은 뿌리로 보인다)

c. 현재 상황 및 코드
================================================================

  [ 콘솔 로그의 시간 순서 (Play 1회분, UTC) ]
    11:52:19  Avoid 씬 로드 완료 — 클리어를 기다리는 중
    11:52:47  변수 'Avoid.hitCount' 를 찾을 수 없음   ← ★ 클리어 전
    11:53:21  [GameController] 클리어
    (이후 VN 복귀 없음)

  - hitCount 오류는 After 대본(AvoidChapterTest_After.txt)의
    if ($Avoid.hitCount == 0) 에서 난다. 이 줄은 [wait]startAvoid 가
    끝난 뒤에야 실행돼야 하는데, 피하기를 하는 도중(28초 시점)에
    이미 실행됐다.
    → [wait]startAvoid 가 "클리어를 기다리지 않고 중간에 끝났다"

  [ 원인 코드 — ConversationManager.cs 195~220행 LINE_RunCommands ]
    while (!cw.IsDone)
    {
        if (userPrompt)
        {
            CommandManager.instance.StopCurrentProcess();   // ★
            userPrompt = false;
        }
        yield return null;
    }

  - [wait] 명령을 기다리는 동안 userPrompt (사용자가 "다음" 신호를
    보냄) 가 true 가 되면, 실행 중인 명령을 강제 종료(Kill)한다.
    원래 목적은 "wait 가 걸린 연출을 사용자가 건너뛰기" 이다.
  - startAvoid 도 [wait] 로 기다리는 명령이라 똑같이 적용된다.
    피하기 도중에 "다음" 신호가 한 번 들어가면 StartAvoid 코루틴이
    죽는다.

  [ 그 결과 일어나는 일 ]
  1. StartAvoid 코루틴이 종료됨 → LINE_RunCommands 의 대기가 풀림
  2. VN 대본이 다음 줄로 넘어가 After 파일을 load 하고 조건문 실행
     (변수가 없어 hitCount 오류)
  3. 그동안 Avoid 씬은 그대로 떠 있고 플레이 계속 가능
  4. 클리어 → AvoidSession.Complete() 로 IsFinished 가 true 가 되지만
     "IsFinished 를 기다리던 StartAvoid 코루틴" 이 이미 죽어서
     ReturnToVN() 이 호출되지 않음 → CLEAR 에서 멈춤

  [ 아직 확인하지 못한 것 — "다음" 신호가 어디서 들어왔는가 ]
  - startAvoid 는 VN 입력을 꺼두지만(PlayerInputManager.SetInputEnabled
    (false)) 아래 경로는 그 설정과 상관없이 신호가 들어갈 수 있음.
    어느 쪽인지 코드만으로는 확정하지 못함
    · DialogueSystem.OnUserPrompt_Next 를 직접 부르는 UI 클릭
      (대사창/배경 클릭, 버튼 등)
    · startAvoid 직전의 대사 줄에서 남은 userPrompt = true
      (사용자 입력 대기가 끝나고 신호가 소비되지 않은 채 남은 경우)
    · 설정창(SettingsPanel) 열고 닫기에 따른 입력 상태 변화

d. 해결을 위해 생성하거나 변경해야 하는 내용
================================================================

  "건너뛰기로 startAvoid 를 죽이지 못하게" 한다. 두 단계로 막는다.

  1. 피하기 진행 중에는 userPrompt 를 소비/무시
     - AvoidSession 에 "진행 중" 상태(IsRunning)를 둔다.
       (Begin 에서 true, 클리어 후 ReturnToVN 끝에서 false)
     - LINE_RunCommands 의 대기 루프에서 피하기 진행 중이면
       StopCurrentProcess 를 부르지 않고 userPrompt 만 false 로 되돌린다.
  2. startAvoid 진입 직전에 남아 있는 userPrompt 를 비운다
     (이미 눌려 있던 신호가 진입하자마자 명령을 죽이는 것을 방지)

  [ 확인을 위한 선행 작업 ]
  - 정확히 어느 입력이 신호를 보냈는지 알기 위해
    ConversationManager 의 userPrompt = true 가 되는 지점(48행)에
    임시 로그를 넣어 호출 스택을 찍어 본다. 이 결과에 따라
    d-1 의 근본 해결(신호 발생원 차단)을 추가할지 정한다.


================================================================
e. 다른 방법들 중에서 왜 d의 방식으로 만든 것인지
================================================================

  [ 대안 1 : startAvoid 를 [wait] 없이 쓰고 VN 이 스스로 기다리게 하기 ]
  - 대본이 선형이라는 장점(3-c 결정)을 잃고, 대본마다 복귀 처리를
    따로 써야 함

  [ 대안 2 : LINE_RunCommands 의 건너뛰기 기능을 전부 제거 ]
  - 다른 [wait] 연출(페이드, 이동 등)의 건너뛰기까지 사라짐

  [ 대안 3 : 입력을 더 철저히 막기 ]
  - 신호가 UI 클릭 등 다른 경로로 들어올 수 있어 한 곳을 막아도
    새는 곳이 남음. 하지만 근본 차단으로는 가치가 있어 d 의
    선행 확인 결과에 따라 병행

  [ 채택 : "피하기 중에는 건너뛰기 무시" + 진입 시 신호 비우기 ]
  - 건너뛰기 기능은 그대로 두고, 피하기에서만 예외로 둠.
    입력이 어디서 들어오든 StartAvoid 가 죽지 않으므로 안전함


================================================================
f. 어떤 순서로 진행할 것인지
================================================================

  1. (확인) userPrompt = true 지점에 임시 로그 → 재현해서 호출 스택 확인
  2. AvoidSession 에 IsRunning 추가
  3. ConversationManager.LINE_RunCommands 대기 루프 수정
  4. StartAvoid 진입 시 남은 userPrompt 비우기
  5. 컴파일 확인 후 Play : VisualNovel → startAvoid → 피하기 중
     Space/Enter/클릭을 눌러도 계속 진행되고, 클리어하면 VN 으로
     복귀해 After 대본이 이어지는지 확인
  6. 오답 재진입(무기를 뽑는다 → startAvoid → restartDialogue)과
     시간 초과 재도전에서도 같은 흐름이 되는지 확인
  7. 확인용 로그 제거, Record 에 기록

h. 주의할 점
================================================================

  ■ 이 문서의 원인(건너뛰기가 StartAvoid 를 죽임)은 로그의 시간 순서와
    코드(LINE_RunCommands)로 추정한 것이다. 입력 발생원은 아직
    확인하지 못했다. 임시 로그로 확정한 뒤 수정할 것

  ■ ConversationManager 는 VN 엔진 본체이므로 수정은 대기 루프의
    조건 한 곳으로 최소화한다

  ■ IsRunning 이 true 로 남아 있으면 이후 [wait] 건너뛰기가 계속
    막힘. 시간 초과 재도전/오답 재진입/씬 강제 종료 경로에서도
    반드시 false 로 돌아오는지 확인 (Begin 에서 초기화)

  ■ Avoid.unity 단독 Play 는 이 경로(startAvoid)를 타지 않으므로
    CLEAR 에서 멈추는 것이 정상. VisualNovel 씬에서 시작해야 확인 가능
