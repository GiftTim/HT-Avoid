b. 문제점
================================================================

  VN 대본이 조건문 if ($Avoid.hitCount == 0) 을 실행하는 순간 아래
  오류가 나고, 조건 평가가 실패한다.

    변수 'Avoid.hitCount'을(를) 찾을 수 없습니다
    (TagManager.InjectVariables → LogicalLineUtils.EvaluateCondition
     → LL_Condition.Execute)

  $Avoid.hitCount 는 피하기를 클리어한 뒤에야 만들어지는 변수인데,
  그 전에(또는 만들어지지 않은 상태에서) 읽혀서 생기는 오류.


================================================================
c. 현재 상황 및 코드
================================================================

  [ 변수가 만들어지는 곳 ]
  - AvoidSession.WriteToVariables() (AvoidSession.cs 65~71행)
    : Avoid.hitCount / retryCount / remainingTime / cleared 를
      없으면 CreateVariable, 있으면 TrySetValue
  - 이 함수는 CMD_DatabaseExtension_Avoid.StartAvoid 의 49행,
    "클리어를 기다리는 while 루프가 끝난 뒤"에만 호출된다

  [ 변수가 읽히는 곳 ]
  - Resources/Dialogue Files/Test/AvoidChapterTest_After.txt 3행
      if ($Avoid.hitCount == 0)
  - AvoidChapterTest.txt 가 [wait]startAvoid(Stage1) 다음에
    load(-f Test/AvoidChapterTest_After) 로 이 파일을 불러온다

  [ 정상 흐름 ]
  AvoidChapterTest → startAvoid(클리어까지 대기) → WriteToVariables
  → load(After) → $Avoid.hitCount 읽기
  → 이 순서로 가면 변수가 이미 있어서 오류가 나지 않는다.

  [ 그래서 오류가 나는 경우 (코드상 추정 — 재현 경로는 확인하지 못함) ]
  1. After 대본을 startAvoid 없이 직접 재생한 경우
     (TestDialogueFiles 의 fileToRead 를 After 로 바꾼 테스트 등.
      현재 VisualNovel.unity 는 AvoidChapterTest 를 가리키고 있음)
  2. 세이브 파일을 불러온 경우
     (VNGameSave.SetVariableData 가 TrySetValue 만 써서, 아직 만들어지지
      않은 Avoid.* 변수는 복원되지 않고 건너뜀 → 새 실행에서 After 구간을
      다시 읽으면 변수가 없음)
  3. startAvoid 가 [wait] 없이 쓰여 클리어 전에 다음 줄로 넘어간 경우
     (현재 대본은 [wait] 를 쓰고 있어 해당하지 않음)

  ※ 콘솔 로그에는 스택트레이스만 있고 "어떤 대본을 어떻게 실행했는지"
    는 없어서 위 셋 중 무엇인지는 확정하지 못했다.

  [ 참고 ] 변수가 없을 때의 동작
  - TagManager.InjectVariables 가 오류를 찍고 $Avoid.hitCount 를 치환하지
    않은 채 넘어가므로, 조건식이 "$Avoid.hitCount == 0" 문자열 그대로
    비교되어 거짓 분기("몇 번 맞았지만...")로 흘러갈 수 있다

d. 해결을 위해 생성하거나 변경해야 하는 내용
================================================================

  "읽히는 시점에 변수가 항상 존재하도록" 기본값을 미리 만들어 둔다.

  1. AvoidSession 에 EnsureVariables() 추가
     - Avoid.hitCount=0 / retryCount=0 / remainingTime=0 / cleared=false
       를 "없을 때만" 만든다 (이미 있으면 건드리지 않음)
  2. AvoidSession.Begin() 끝에서 EnsureVariables() 호출
     - Begin 은 Play 시작(ResetOnPlay)과 [startAvoid] 진입 때마다 불리므로
       VN 대본이 읽기 전에 변수가 항상 만들어져 있게 된다
  3. WriteToVariables() 는 그대로 (클리어 시 실제 값으로 덮어씀)

  [ 선택 사항 — 필요하면 별도로 ]
  - 세이브 복원(VNGameSave.SetVariableData)에서 없는 변수를 만들어 주는
    동작은 VN 엔진 본체 변경이라 이번에는 건드리지 않는다.
    (1~2 로 Avoid.* 는 미리 만들어져 있으므로 TrySetValue 가 성공함)

h. 주의할 점
================================================================

  ■ 기본값 hitCount=0 때문에, 피하기를 하지 않고 After 를 재생하면
    "한 번도 맞지 않았다" 분기로 갈 수 있다. 오류는 사라지지만 분기 결과가
    실제 플레이와 다를 수 있으므로 cleared(기본 false)로 구분 가능

  ■ Begin() 은 Play 시작 시 SubsystemRegistration 단계에서도 호출되므로
    VariableStore 쪽 초기화 순서가 문제 없는지 컴파일/Play 로 확인할 것
    (VariableStore 는 static 이라 접근 시 자동 생성됨)

  ■ EnsureVariables 는 "없을 때만" 만들어야 한다. 이미 클리어 결과가
    들어 있는 변수를 Begin 이 0 으로 덮어쓰면 안 됨

  ■ 이 문서의 원인은 코드만 보고 세운 추정이다. 재현 경로를 알려 주면
    확정할 수 있음
