b. 문제점
================================================================

  Avoid.unity Play 중 콘솔에 아래 오류가 발생한다.

    Particle Velocity curves must all be in the same mode

  가속 연출(캐릭터 주변 바람 줄기 / 화면 속도선)의 파티클 속도 모듈
  설정과 관련된 오류로 보인다. 연출이 정상적으로 나오는지도 함께
  확인이 필요하다.


================================================================
c. 현재 상황 및 코드
================================================================

  ※ 이번 세션에서 실제 파일을 읽어 확인한 내용. 오류의 정확한 발생
    지점(스택트레이스)은 아직 확인하지 못했음 — 아래는 코드상의 추정

  이 오류 메시지는 Velocity over Lifetime 모듈의 x / y / z 세 곡선이
  서로 다른 모드(Constant / Curve / TwoConstants 등)일 때 Unity 가
  내는 것이다.

  Velocity over Lifetime 을 코드로 설정하는 곳이 두 군데 있다.

  [ PlayerSpeedAura.cs — CreateStreaks() 99~104행 ]
    velocity.enabled = true;
    velocity.space   = World;
    velocity.x       = 0;
    velocity.y       = 0;
    velocity.z       = -streakSpeed;

  [ SpeedEffect.cs — CreateLines() 118~123행 ]
    velocity.enabled = true;
    velocity.space   = Local;
    velocity.x       = 0;
    velocity.y       = 0;
    velocity.z       = -lineSpeed;

  두 곳 모두 모듈을 먼저 켠(enabled = true) 뒤에 x → y → z 를 하나씩
  대입한다. 대입한 값(float)은 Constant 모드로 바뀌는데, 하나씩 바뀌는
  중간 시점에 세 곡선의 모드가 서로 달라 검사에 걸릴 가능성이 있다.
  (새로 AddComponent 한 ParticleSystem 의 기본 모드가 무엇인지는
  확인하지 못함)

  현재 씬에는 PlayerSpeedAura 만 부착되어 있고 SpeedEffect 는 연결되어
  있지 않으므로, 지금 발생하는 오류는 PlayerSpeedAura 쪽일 가능성이 높다.


================================================================
d. 해결을 위해 생성하거나 변경해야 하는 내용
================================================================

  1. 먼저 콘솔의 스택트레이스로 오류가 PlayerSpeedAura / SpeedEffect 중
     어느 쪽에서 나는지 확인한다 (추정을 확정으로 바꾸기 위함)
  2. Velocity over Lifetime 설정을 "세 곡선을 같은 모드로 한 번에"
     지정하도록 바꾼다
     - velocity.enabled = true 를 x / y / z 대입 "뒤"로 옮긴다
       (모듈이 꺼진 상태에서 세 값을 모두 Constant 로 맞춘 뒤 켬)
     - x / y / z 모두 new ParticleSystem.MinMaxCurve(값) 으로 명시해
       같은 Constant 모드임을 분명히 한다
  3. 같은 패턴이 있는 SpeedEffect.cs 도 함께 고친다 (아직 씬에는 없지만
     부착하는 순간 같은 오류가 나므로)
  4. 위 방법으로도 오류가 남으면, 모드가 달라지는 지점을 로그로 찍어
     (velocity.x.mode / y.mode / z.mode) 원인을 확인한다


================================================================
e. 다른 방법들 중에서 왜 d의 방식으로 만든 것인지
================================================================

  [ 속도 방식 : Velocity over Lifetime vs startSpeed + 방출 방향 ]
  - Velocity over Lifetime (현행 유지) : 줄기를 +Z 에서 -Z 로 일직선으로
    흘리는 데 가장 단순하고, 이미 값(streakSpeed 등)이 인스펙터에서
    조정되는 구조임. 방식을 바꾸지 않고 설정 순서만 고치는 쪽이
    변경이 가장 작음

  [ 대안 : startSpeed 로 -Z 방향 발사 ]
  - 방출 모양/회전을 -Z 쪽으로 돌려야 해서 연출 구성이 바뀜.
    d 로 해결되지 않을 때의 예비안

  [ 대안 : 파티클을 프리팹으로 만들어 에디터에서 설정 ]
  - 근본적으로 이런 모드 불일치가 안 생김. 다만 그림 리소스가 정해지는
    시점(4일차 이후)의 작업이라 지금은 보류


================================================================
f. 어떤 순서로 진행할 것인지
================================================================

  1. 콘솔 스택트레이스로 발생 위치 확인
  2. PlayerSpeedAura.cs 의 velocity 설정 순서 수정
  3. SpeedEffect.cs 도 같은 방식으로 수정
  4. Unity 에서 컴파일 확인 후 Avoid.unity Play : 앞 방향키를 눌러
     가속했을 때 오류 없이 줄기가 보이는지 확인
  5. 이상 없으면 Record 에 한 줄 남김


================================================================
g. 어디가 어떻게 변경되는지
================================================================

  [ 수정 ] Assets/Scripts/Avoid/Core/PlayerSpeedAura.cs
    - velocity 블록의 대입 순서/형식 (enabled 를 마지막으로)
  [ 수정 ] Assets/Scripts/Avoid/Core/SpeedEffect.cs
    - 같은 변경

  [ 변경 없음 ] GameController.cs, 씬 파일, 입력 설정

h. 주의할 점
================================================================

  ■ 이 문서의 원인은 코드만 보고 세운 추정이다. 스택트레이스로 발생
    위치를 확인하기 전에는 확정하지 말 것

  ■ ColorOverLifetime 등 다른 모듈의 Gradient 설정은 이 오류와 무관해
    건드리지 않음

  ■ 수정 후 줄기 방향/속도(streakSpeed 30, lineSpeed 55)는 그대로여야
    함. 설정 순서만 바꾸므로 연출 결과는 달라지지 않아야 함
